Hosted API failover validation: standard smoke tests (chat + embeddings)

h1. Purpose
Provide a standardized set of end-to-end smoke tests to run during a failover and immediately after traffic cutover. These tests are designed to catch common failure modes (auth/JWKS, routing, streaming stability, token accounting).

h1. Preconditions
- You have a valid production API key with admin approval to run smoke tests
- You know the current target region distribution (from trafficctl)
- You can observe dashboards for error rate/latency and token accounting lag

h1. Smoke test 1: chat completions (non-streaming)
Command:
```
curl https://api.redwoodinference.com/v1/chat.completions \
  -H "Authorization: Bearer $RW_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"redwood/verified-llama-3-70b","messages":[{"role":"user","content":"Reply with the single word OK."}]}'
```
Expect:
- HTTP 200
- Response contains "OK"
- Latency not grossly out of range

h1. Smoke test 2: chat completions (streaming)
Command:
```
curl -N https://api.redwoodinference.com/v1/chat.completions \
  -H "Authorization: Bearer $RW_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"redwood/verified-llama-3-70b","stream":true,"messages":[{"role":"user","content":"Stream the word OK one character at a time."}]}'
```
Expect:
- Connection stays open
- Tokens arrive steadily (not all at once)
- No early disconnect

h1. Smoke test 3: embeddings
Command:
```
curl https://api.redwoodinference.com/v1/embeddings \
  -H "Authorization: Bearer $RW_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"redwood/verified-bge-large","input":["failover smoke test"]}'
```
Expect:
- HTTP 200
- embeddings array present

h1. Token accounting validation
During/after cutover, explicitly check:
- billing_token_events_lag_seconds < 300
- no sustained errors in token accounting write path

If lag grows > 5 minutes for > 10 minutes, inform IC and consider rollback/partial rollback.

h1. Notes
- These smoke tests are intentionally minimal; do not run large prompts during an incident.
- If you suspect region pinning due to DNS caching, repeat tests after TTL has elapsed and watch regional request counters.
