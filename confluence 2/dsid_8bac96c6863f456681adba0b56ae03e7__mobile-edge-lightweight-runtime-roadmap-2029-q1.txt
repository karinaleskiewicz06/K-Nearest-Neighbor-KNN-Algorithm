Mobile Edge Lightweight Runtime — Roadmap & Launch Plan (2029 Q1)

Summary
-------
This document describes Redwood's plan for a lightweight mobile-edge runtime ("Mobile Edge Lightweight Runtime", or MELR) targeted for Q1 2029 GA. MELR enables customers to run constrained, quantized model variants on consumer and enterprise mobile devices with a unified developer experience for fallback to hosted/Dedicated deployments. The runtime focuses on deterministic latency, small memory footprint, secure on-device keys, and integrated usage telemetry for consumption-aware pricing.

Goals and non-goals
-------------------
Primary goals:
- Offer a supported, Redwood-integrated runtime that runs curated model variants on modern mobile SoCs (ARMv8.2+ with NEON and optional NPU) and Apple silicon.
- Achieve median generation latency <= 120 ms for typical 16-token completions for the 3B-class mobile-quantized variant.
- Keep peak RAM footprint <= 450 MB for the primary 3B mobile variant and <= 1.2 GB for 7B mobile variants.
- Provide secure local key handling with automatic optional sync to customer-managed KMS for private deployments.
- Instrument per-session usage and economy metrics for per-device or per-endpoint metered billing.
- Integrate the same model-variant compatibility matrix and fallback route policy used by Hosted/Dedicated.

Out-of-scope:
- Full parity with server-grade kernels and large-sequence throughput optimizations.
- Support for custom third-party kernel binaries at GA (will be supported in later phases).

Target personas and customers
----------------------------
- Mobile product engineers building native apps that require low-latency completions (chat, assistant features, offline classification).
- Platform teams at regulated enterprises needing on-device processing for PII-sensitive paths.
- ISVs shipping consumer apps where cost-per-session and battery impacts are first-order concerns.

Success metrics (KPIs)
----------------------
- Performance: median latency <= 120ms for 16-token completion on 3B mobile variant across 60% of sampled devices in Redwood Device Pool A within 30 days of GA.
- Resource: 95th percentile peak RAM <= 450 MB for 3B variant.
- Reliability: <1% crash rate attributable to MELR across installs with signal collection opt-in.
- Adoption: 50 customers (~100k devices) integrated and active within 6 months of GA.
- Economics: per-session infra-equivalent cost reduction >= 40% relative to hosted for short-turn interactive sessions.

Constraints and technical considerations
---------------------------------------
- Supported models: curated, Redwood-verified mobile variants (naming example: rwd-x86-7b-q4_0-mobile, rwd-3b-q4_8-mobile). Variants are compiled and signed by Redwood.
- Security: runtime must support secure enclave/Keychain storage and an optional attestation handshake for enterprise private deployments.
- Energy: memory and CPU budgets prioritized; background prefetch allowed with explicit developer opt-in.
- Telemetry: only minimal usage metrics and anonymized RTT/latency histograms are collected by default; detailed traces require explicit customer consent.

High-level product capabilities
------------------------------
1) Lightweight inference engine
- Small binary (<= 12 MB post-strip) with dynamic loading of quantized weights.
- Single-request streaming support with configurable chunk sizes and progressive decoding.

2) Hybrid routing and sync
- Local-first execution with automatic fallthrough to Hosted/Dedicated model variants on policy violation (e.g., sequence length > local limit, unsupported op).
- Local telemetry and periodic sync to the customer's Redwood control plane.

3) Developer ergonomics
- Unified SDK (Kotlin, Swift) that mirrors server-side Redwood API surface: generation, embeddings, and function/tool calling shims.
- Local test harness and emulator for CI.

4) Pricing and metering primitives (GA)
- Two billing modes at GA: per-active-device-per-month (device-seat) and per-token-equivalent (metered) with device-local aggregation and periodic reporting.
- Default tier: up to 2500 interactive requests/device/month included (device-seat); metered overage billed by aggregated token-equivalent.

Design tradeoffs and rationale
-----------------------------
- Quantization vs accuracy: We prioritize aggressive quantization (q4_0/q4_8) for footprint reduction; quality monitoring hooks (continuous evals) will detect regressions per-customer prompt-set.
- Binary minimalism vs extensibility: initial GA focuses on a minimal, tightly-tested runtime to reduce attack surface. Plugin architecture deferred to v1.2.

Roadmap and milestones (high level)
----------------------------------
- 2026-Q4: Feasibility spike, device pool creation, kernel validation on ARM/Apple silicon.
- 2027-Q2: Reference quantized model family training and CI cross-compile pipelines.
- 2027-Q4: Internal alpha: limited partners, SDK proto with 3B variant.
- 2028-Q2: Beta: public SDK (Kotlin/Swift), telemetry hooks, hybrid routing pilot.
- 2028-Q4: GA candidate: stability and security hardening, enterprise key sync.
- 2029-Q1: GA launch with pricing tiers and console integration.

Rollout phases and checklist
---------------------------
1) Alpha (internal / select partners) - Deliverables: signed runtime, reference models, SDK alpha, telemetry pipeline. - Owners: eng-serving-runtime (lead: Mara Jensen), product (Asha Patel). - Duration: 3 months.
2) Beta (wider customers) - Deliverables: public SDK, documentation, console activation flow, metrics dashboards. - Pre-launch guardrails: quantization quality gate (<2% regression on key prompt-sets), crash rate <1.5%.
3) GA - Deliverables: pricing page, onboarding templates, migration guide, enterprise key sync API. - Post-GA: developer enablement, performance SLAs for Dedicated fallthrough.

Pricing & packaging notes (initial thinking)
-------------------------------------------
- Device-Seat Plan: $0.95/device/month for up to 10k devices; volume discounts start at 10k+ devices. Includes 2,500 interactive requests/device/month.
- Metered Plan: $0.0006 per token-equivalent aggregated (device reports token-equivalent counts every 24 hours).
- Enterprise On-Prem Pack: annual license + support; pricing bespoke per customer with options for flat metering ingestion into customer billing pipeline.
- Console UX: allow customers to choose billing mode per-tenant and export device-level anonymized usage for chargeback.

Developer experience and docs plan
----------------------------------
- Quickstart: "5-minute local inference" using emulator and sample app (Kotlin/Swift).
- Migration guide: mapping server-side model calls to local SDK, fallthrough semantics, and best-practice prompt shaping for short sequences.
- Security checklist: steps for KMS sync and attestation enrollment.

Migration strategy for existing customers
----------------------------------------
1) Discovery: identify heavy short-interaction routes (median tokens < 40) via Console usage queries.
2) Pilot: invite 5 customers to run MELR in Beta with feature flags and co-monitoring.
3) Gradual rollout: provide opt-in device-seat credits and a migration checklist.
4) Fallthrough safety: ensure all routes have fallthrough-enabled model variants by default.

Security, compliance, and privacy
--------------------------------
- Data residency: by default, inference inputs are processed locally. Periodic telemetry is aggregated and stored in Redwood's telemetry buckets in customer-chosen region.
- Key handling: support OS Keychain/Keystore; enterprise customers can require HSM-backed attestation for provisioning.
- Compliance: evaluate MELR for SOC2 and HIPAA behavioral requirements prior to GA for enterprise templates.

Operational readiness and SRE expectations
----------------------------------------
- SLOs: fallback-to-hosted success rate >= 99%, telemetry ingestion latency < 5 minutes for active device reports.
- Alerting: continuous percent-failures across installs, abnormal battery usage signals, crash anomaly detection.
- Runbooks: include steps for revoking a compromised runtime signature and remote disable of specific model variants.

Risks and mitigation plan
-------------------------
- Risk: quantized model quality regressions cause user-impacting behavior. Mitigation: continuous evals on customer prompt-sets and staged rollout with quality gates.
- Risk: device fragmentation leads to poor performance on older devices. Mitigation: device pool stratification and explicit minimum supported device list for GA.
- Risk: telemetry privacy concerns. Mitigation: strong opt-out UX and minimal default telemetry.
