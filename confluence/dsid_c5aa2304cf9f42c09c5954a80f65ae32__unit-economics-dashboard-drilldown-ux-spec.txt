Unit Economics Dashboard (Internal) — Drilldown UX Spec (v1)

## Summary
This document specifies the Console UX for the internal **Unit Economics** dashboard v1, with emphasis on the filter bar, drilldown navigation, top-N tables, and empty/error-state behavior.

Primary metric: **Blended $/1M output tokens** (finance-aligned). Users can drill down by:
- Model (incl. model version and quantization profile)
- Region
- Customer tier (Self-serve / Dedicated / Private / Enterprise)

Non-goals (v1): external customer-facing cost views; automated optimization actions.

---

## Personas and primary jobs-to-be-done
### Finance (CFO/FP&A)
- Confirm unit cost trends are explainable and reconcile to spend inputs.
- Pull quarter-to-date (QTD) summaries with clear caveats.
- Identify unit-cost outliers by region/tier/model.

### Product (Console/Optimize)
- Prioritize cost optimization work based on impact size and affected segments.
- Detect regressions after runtime/infra/model changes.

### Engineering (Telemetry/Runtime/SRE)
- Triage anomalies: missing tokens, dimension coverage gaps, and cost spikes.
- Validate whether caching/batching/quantization changes moved economics.

## Page information architecture
### Entry points
- Console left nav (internal-only): **Analytics → Unit Economics**
- Deep links from alerts/runbooks (when data quality issues fire)

### Pages (v1)
1) **Overview** (default)
   - KPI tiles (current window)
   - Time series
   - Top-N tables (Models, Regions, Tiers)

2) **Drilldown detail** (one pattern, parameterized by dimension)
   - Dimension header (e.g., Model: `rw-mistral-7b`)
   - Time series + breakdowns of remaining dimensions
   - Supporting signals panel (cache hit rate, batching efficiency, avg output length, streaming share, quant profile mix)

## Global filter bar (applies to Overview + Drilldowns)
Filter bar is pinned at top of page content.

### Filters (left to right)
1) **Time range** (required)
   - Defaults: Last 7 days
   - Presets: Last 24h, Last 7d, Last 30d, QTD, Custom
   - Custom supports start/end date-time; timezone selector defaults to **UTC** with a visible indicator.

2) **Model** (optional, multi-select)
   - Values from canonical model identifier mapping.
   - Display label: marketing alias (if present) + internal id in tooltip.
   - Selecting a model narrows tables and time series.

3) **Model version** (optional, conditional)
   - Enabled when exactly one model is selected.
   - Default: All versions.

4) **Quantization profile** (optional)
   - Default: All
   - Allowed values are from controlled vocabulary (per telemetry standard). Unknown/other values grouped as `Other/Unknown`.

5) **Region** (optional, multi-select)
   - Uses normalized canonical region names (e.g., `us-east`, `eu-west`).
   - Unknown values grouped as `Unknown` and are selectable.

6) **Customer tier** (optional, multi-select)
   - Values: Self-serve, Dedicated, Private, Enterprise
   - Tooltip clarifies derivation (billing/contract/routing flags).

7) **Advanced** (collapsible)
   - Streaming: All / Streaming only / Non-streaming only
   - Compare to: Previous period (same duration) [toggle]

### Filter interaction rules
- Any change applies immediately (no “Apply” button) with debounce (300–500ms) to avoid rapid refetch.
- Show a small “Updating…” indicator in the filter bar while requests are inflight.
- URL is the source of truth for filter state (shareable deep link). Query params:
  - `from`, `to`, `tz`, `models`, `version`, `quant`, `regions`, `tiers`, `streaming`, `compare`
- Provide “Reset to defaults” action.

### Guardrails
- If selected filters yield >N series (e.g., >25 in a chart), show a warning and force aggregation (see Chart section).
- If the user selects a combination known to be slow (e.g., long custom range + high-cardinality breakdown), show inline guidance: “Try narrowing the time range or selecting fewer dimensions.”

## Core visual components

## 1) KPI tiles (Overview + Drilldown)
Tiles show the current time window and (if enabled) delta vs previous period.

Required tiles (v1):
- **Blended $/1M output tokens**
- **Total output tokens**
- **Total attributed cost ($)**
- **Data completeness** (percent of expected hourly partitions present)

Tile formatting:
- $/1M output tokens: show with 2 decimals if >= $1, else 4 decimals (e.g., $0.1234).
- Deltas: show % change with sign.
- Tooltips:
  - Define blended cost and scope.
  - Link: “Metric definition” → metric dictionary page.

## 2) Time series chart
Default chart: **Blended $/1M output tokens over time** (hourly for <= 72h; daily otherwise).

Controls:
- “Group by” (single dimension) dropdown on Overview: None (default), Model, Region, Customer tier.
- On Drilldown pages: group-by defaults to the *remaining* most relevant dimension (see drilldown sections).

Chart behaviors:
- If group-by is None: single line.
- If group-by is set: multi-line chart limited to top 10 by output tokens; remaining grouped into “Other”.
- Hover tooltip shows:
  - $/1M output tokens
  - output tokens
  - attributed cost
  - completeness/confidence indicator for that bucket

Comparison mode:
- If “Compare to previous period” is enabled, show dashed line(s) for previous period with same color family.

## 3) Top-N tables
Three tables on Overview (stacked). Default sort: highest attributed cost ($) descending.

Tables:
- **Top Models**
- **Top Regions**
- **Top Customer Tiers**

Common columns (v1):
1) Name (dimension value)
2) Blended $/1M output tokens
3) Output tokens
4) Attributed cost ($)
5) Cache hit rate (if available)
6) Batching efficiency (if available)
7) Streaming share
8) Data completeness

Column definitions:
- Cache hit rate: displayed as %; tooltip clarifies KV/prefix cache definition.
- Batching efficiency: displayed as %; tooltip clarifies definition (effective utilization vs ideal).
- Streaming share: % of requests that were streaming.

Table interaction:
- Rows are clickable to drill down (see Drilldown navigation).
- Column sorting enabled for: $/1M, output tokens, cost, completeness.
- Pagination: default 10 rows, expandable to 25/50.
- Search within dimension values for Models and Regions.

Privacy & sensitivity:
- No customer identifiers in any table.
- Suppress buckets with extremely low volume to avoid over-interpretation and potential leakage:
  - If a row has < 0.5% of total output tokens for the view (or < configurable absolute minimum), display it aggregated into “Other” (exact threshold TBD with Finance/Security).

## Drilldown navigation

## Navigation model
Drilldown pages use the same route with typed parameters:
- `/internal/unit-economics` (Overview)
- `/internal/unit-economics/model/<model_id>`
- `/internal/unit-economics/region/<region_id>`
- `/internal/unit-economics/tier/<tier_id>`

### Entry actions
- Clicking a row in any Top-N table navigates to the corresponding drilldown.
- Clicking a legend item in the chart (group-by mode) navigates to that drilldown (if dimension is eligible).

### Breadcrumbs
At top of drilldown detail:
- `Unit Economics` → `Model: rw-llama3-70b` (or Region/Tier)

### Context preservation
- Drilldown retains all global filters (time range, quant profile, streaming, etc.).
- Drilldown implicitly pins the selected dimension value; it is shown as a “locked” pill in the filter bar with an “X” to remove and return to Overview.

## Drilldown page layouts

## A) Model drilldown
Header:
- Model display name (alias + id)
- Optional subheader chips: selected model version, selected quant profile

Primary content:
1) KPI tiles (same as Overview)
2) Time series chart (default group-by: **Region**) with toggle to switch group-by to Customer tier
3) Breakdown tables:
   - “Regions for this model” (top 25)
   - “Customer tiers for this model” (all tiers)
   - If model version is not pinned: “Model versions for this model”
   - If quant profile is not pinned: “Quant profiles for this model”

Supporting signals panel (right rail or below, depending on screen width):
- Cache hit rate trend
- Batching efficiency trend
- Avg output length (tokens) trend
- Prefill/decode ratio (if instrumented)
- Notes: “Signals are diagnostic; attribution is directional.”

## B) Region drilldown
Header:
- Region canonical name (e.g., `eu-west`) + tooltip listing underlying mapped providers/labels.

Primary content:
1) Time series chart (default group-by: **Model**)
2) Tables:
   - “Models in this region”
   - “Customer tiers in this region”
   - “Quant profiles mix in this region”

Region caveat callout (inline):
- If the region has known cost-rate-card updates in the selected window, show “Rate card changed on <date>” with link to methodology note.

## C) Customer tier drilldown
Header:
- Tier name + tooltip describing derivation and edge cases.

Primary content:
1) Time series chart (default group-by: **Model**)
2) Tables:
   - “Models for this tier”
   - “Regions for this tier”
   - “Quant profiles for this tier”

Tier caveat callout (inline):
- Dedicated/Private tiers may have more pronounced idle cost allocation effects; add a persistent info note linking to ADR.

## Empty states, error states, and data quality behaviors

## Definitions
- **No data**: query returned zero rows for the selected filters.
- **Partial data**: some expected hourly partitions missing OR missing critical dimensions above threshold.
- **Stale data**: data freshness SLO violated (e.g., latest hour not loaded by target time).

## Loading states
- Use skeleton loaders for tiles and tables.
- Time series shows a faint placeholder grid with “Loading data…” label.
- Preserve previous data on minor filter tweaks when possible; show “Updating…” to reduce perceived flicker.

## Empty state (no data)
Show a dedicated empty state panel:
- Title: “No unit economics data for this selection”
- Body copy:
  - “Try widening the time range or removing one or more filters.”
  - If streaming-only is enabled: “Streaming-only views may have limited coverage for older periods.”
- Actions:
  - Button: “Reset filters”
  - Link: “View pipeline status” (links to internal observability dashboard)

## Partial data state (incomplete coverage)
When completeness < target (thresholds per SLO doc):
- Show a **yellow banner** at top of page:
  - “Data is incomplete for the selected time range (X% of expected hours present). Values may change after backfill.”
  - Link: “See runbook”
- In charts/tables, show a small “Low confidence” indicator next to affected series/rows.

## Stale data state
When latest data is older than freshness target:
- Show **red banner**:
  - “Data is stale (latest hour: <timestamp UTC>).”
  - Link: “Incident channel / runbook”

## API error state
If API returns an error:
- Display a non-blocking error toast plus a full-width error panel if content cannot load.
- Panel includes:
  - “We couldn’t load unit economics data.”
  - “Request ID: <id>”
  - “Retry” button
  - Link to runbook

## Dimension coverage issues
If a high fraction of rows have `Unknown` for a critical dimension (region/tier/model):
- Show an inline warning in the relevant table header:
  - “High ‘Unknown’ coverage for Region (12%). Investigate region normalization.”
  - Link to region normalization plan and/or runbook.

## Formatting, rounding, and interpretation safeguards
To avoid misinterpretation (per internal visualization guidelines):
- Always display metric unit in labels: “$/1M output tokens”.
- Use consistent number formatting across tiles, charts, and tables.
- For very small denominators:
  - If output tokens < minimum threshold for the row, show $/1M as “—” and tooltip: “Insufficient volume for stable unit cost.”
- Deltas should be suppressed when the previous period has insufficient volume.

Required tooltip copy (v1):
- “Blended $/1M output tokens includes allocated compute + shared overhead per the finance methodology. It is not the marginal cost of an additional request.”

---

## Permissions and access control UX
- Page is behind an internal feature flag and RBAC check.
- If a user lacks access:
  - Show “You don’t have access to Unit Economics.”
  - Provide instructions: “Request access via #internal-tools-support” (or internal request system).
  - Do not reveal any metric values.

---

## Accessibility and usability requirements
- Keyboard navigation must work for filter bar controls and table row drilldowns.
- Color choices for multi-series charts must be color-blind safe; do not rely on color alone for compare mode (use line style).
- Tooltips must be accessible (focus-triggered, not hover-only).

## Appendix A: UI copy strings (v1)
- Banner (incomplete): “Data is incomplete for the selected time range ({{completeness}}%). Values may change after backfill.”
- Banner (stale): “Data is stale (latest hour: {{timestamp}}).”
- Empty state title: “No unit economics data for this selection”
- Empty state helper: “Try widening the time range or removing one or more filters.”
- Tooltip (metric): “Blended $/1M output tokens includes allocated compute + shared overhead per the finance methodology. It is not marginal cost.”

## Appendix B: Table column glossary (short)
- Output tokens: total metered output tokens attributed to the selection.
- Attributed cost ($): allocated cost for the selection per the attribution model.
- Cache hit rate: fraction of tokens served with KV/prefix cache reuse (definition may vary by runtime path).
- Batching efficiency: utilization proxy representing effective batching vs ideal scheduling.
- Completeness: percent of expected hourly partitions present for the bucket.
