inference-deployment-safety-lab-and-gating-playbook

Overview

This playbook documents the Safety Lab for inference-serving deployments and the CI/CD gating configuration used to promote kernel, runtime, image and Terraform/IaC changes into production GPU pools. It is intended for infra engineers, release owners, SREs and release-cadence owners. The document explains the test harness, the staged canary choreography, automated gating rules, required telemetry, and the rollback criteria used by our deployment orchestrator.

Goals

- Prevent latency and correctness regressions for customer inference workloads caused by runtime/kernel/IaC changes.
- Ensure cost and egress regressions are surfaced during CI preflight.
- Automate safe canaries with clear thresholds and deterministic rollbacks.
- Provide reproducible test artifacts that developers can run locally or in CI.

Scope

Applies to changes that touch any of the following artifacts:
1) GPU runtime binaries, kernels or JIT/compiled code.
2) Serving container images (inference-proxy, allocator-service, warmup-sequencer).
3) Terraform/IaC modules that change GPU pool topology, NAT/egress, or warm-pool sizing.
4) Scheduler and routing policy changes that affect request routing for Dedicated or Hosted routes.

Safety Lab Components

- Canary Grid: a simulated tenant grid that runs synthetic inference traffic across small, medium, and long-sequence profiles.
- Evaluator Harness: automated evals that run ground-truth prompt sets and quality/coverage checks (BLEU/ROUGE/LLM-specific metrics).
- Cost Probe: runs representative workload mix to estimate token-per-second and egress spend delta.
- Warmup/Seeding Monitor: validates KV-cache warmup behaviors and hit-rate after image/TF rollouts.
- Stress and Preemption Test: exercises spot/spot-reserve and preempt scenarios to measure queueing/latency tail-behavior.

Test Matrix (example)

| Category | Synthetic Profiles | Duration | Primary Metrics | Threshold |
|---|---:|---:|---|---|
| Latency baseline | small (<=128 tokens) | 30m | p50/p95/p99 latency | p95 <= 1.25x baseline |
| Long-sequence throughput | long (>=2048 tokens) | 1h | tokens/s, memory growth | tokens/s >= 0.9x baseline |
| KV-cache correctness | mixed prefix | 30m | cache hit-rate, errors | hit-rate >= 95% |
| Cost probe | mixed | 45m | tokens/second-cost, egress | delta <= +15% |
| Quality eval | curated prompts | 30m | correctness, hallucination rate | no statistically significant drop |

Preflight CI Pipeline (high-level)

1. Static checks and policy: run opa/terraform plan checks and image-scan. Fail fast on policy violations.
2. Unit and integration tests for runtime changes.
3. Build artifact and sign image: e.g. cosign sign + attestation.
4. Deploy to Safety Lab Canary Grid (isolated account + warm-pool).
5. Run Safety Lab tests (matrix above).
6. Compare metrics against baseline stored in telemetry.
7. Gate decision: if all thresholds pass -> promote to progressive canary. If any gate fails -> block and file regression ticket.

Gating Rules and Automations

- Hard gates (block merge or promote): OPA/IaC policy violations, security scan high CVE, cosign not present.
- Soft gates (require owner approval if violated): cost delta > 10% but <= 15%, minor regression in p95 (<=1.25x).
- Automatic rollback triggers during canary: sustained p95 > 1.5x baseline for 5 minutes, error-rate increase > 2% absolute, KV-cache misses causing correctness faults.

Staged Canary Rollout (recommended sequence)

1. Canary-1 (5% traffic): run for 15 minutes with full telemetry sampling. If stable ->
2. Canary-2 (20%): run for 30 minutes, exercise warm-pool seeding across zones. If stable ->
3. Canary-3 (50%): run for 60 minutes, enabled autoscaler stress. If stable ->
4. Full rollout (100%) with 10-minute guard window and rollback monitor enabled.

Note: For Dedicated customers with SLA tiers, use a smaller top-level increment (e.g., 3% -> 10% -> 25%) and notify Customer Success.

Required Telemetry and Dashboards

Minimum metrics to collect for each canary:
- per-tenant p50/p95/p99 latency
- tokens/sec and tokens/second-cost
- request error rate and error taxonomy (timeout/kernel-failure/oom)
- KV-cache hit-rate and eviction rate
- GPU memory utilization and SM occupancy
- egress bytes per token and NAT session rates

Dashboards (canonical):
- Safety Lab Compare: baseline vs candidate delta panels (latency, cost, errors).
- Rollout Health: real-time canary percentages and automated trigger logs.
- Preflight Summary: CI run artifacts, cosign attestations, terraform plan summary.

Terraform/IaC and Policy Requirements

- All IaC changes must include a terraform plan output artifact uploaded to the CI artifact store.
- OPA policies must assert: no change that reduces NAT gateway capacity for production pools, no removal of warm-pool resources without explicit approval, and network egress path must have egress-metering sidecars enabled.

Example OPA rule (simplified):
```rego
package redwood.policy
deny[msg] {
  input.resource.type == "aws_nat_gateway"
  input.change == "delete"
  msg = "Deleting NAT gateway without egress mitigation approval"
}
```

Image and Binary Signing

- Build pipeline must cosign all serving images with the build CI key. Attestations must include: git-sha, build-id, tf-plan-id (if IaC included), and test-run-id.
- Image promotion requires: cosign verification step in the promote job.

Local Repro Steps for Engineers

1. Start a Safety Lab local cluster using the dev harness: devctl safetylab up --profile=long-sequence
2. Build the candidate image locally: make build-image && cosign sign --key $COSIGN_KEY registry/redwood/inference:canary
3. Run the preflight: devctl safetylab run --artifact <image> --matrix safety-matrix.yaml
4. Upload the metric snapshot: devctl safetylab snapshot upload --tag <pr-number>

Rollback Playbook (on-call runbook snippet)

1. If automated rollback triggers fire, page the oncall SRE for "inference-rollout".
2. Capture snapshot: curl -s http://rollout-api/internal/snapshot > /tmp/rollout-snap.json
3. Execute emergency rollback: rolloutctl promote --target previous-image --force-restart 1
4. If rollback fails, execute warm-pool isolation: tf apply -var "isolate_warm_pool=true" -auto-approve (restricted privileged run).
5. Postmortem: create postmortem within 48 hours, link to rollout-snap, attach canary metrics.

Change Templates and PR Requirements

Every PR that touches runtime/IaC must include the following checklist in the PR description:
- [ ] Link to terraform plan artifact and OPA policy scan results
- [ ] Cosign attestation present for any image
- [ ] Safety Lab run id and pass/fail status or explanation for skip
- [ ] Owner approval if any soft gate violated

Troubleshooting Appendix

Q: Preflight shows higher p99 latency but p95 is within thresholds.
A: Look at GPU SM occupancy and tail GC events. If only p99 impacted, extend canary to 2x duration and enable enhanced tracing (trace-level=2) for five minutes to collect kernel-level traces.

Q: Cost probe shows 12% egress increase after change.
A: Compare token/egress by route - often caused by ambient telemetry or increased per-token metadata. If within soft gate (<=15%) request engineering review; otherwise block promotion.

CI Job Example (condensed YAML)

```yaml
jobs:
  preflight-safetylab:
    runs-on: runner-gpu-small
    steps:
      - name: terraform plan
        run: terraform plan -out plan.tfout && upload-artifact plan.tfout
      - name: opa policy scan
        run: opa test /policies -e . || exit 1
      - name: build and cosign image
        run: make image && cosign sign --key $COSIGN_KEY $IMAGE
      - name: trigger safety lab
        run: ci-trigger --grid safetylab --image $IMAGE --matrix safety-matrix.yaml
      - name: wait and fetch results
        run: ci-wait --id $RUN_ID && ci-fetch-metrics --id $RUN_ID
```
