Redwood data retention and logging controls (Hosted API, Dedicated, Private)

# Overview
This page describes what Redwood retains related to inference requests, where it is stored, and how retention differs across deployment modes (Hosted API, Dedicated, Private).

This page is intended to support consistent answers during security reviews. For customer-facing statements, use the approved language in the "Customer-facing summary" section and have Security review any deviations.

# Definitions
- **Payload / content**: customer prompts, tool calls, files, and model completions.
- **Operational metadata**: timestamps, latency, token counts, status codes, model id/version, and anonymized routing decisions.
- **Debug capture store**: restricted-access storage used to investigate incidents, suspected abuse, and customer-reported issues.

# What we do NOT do
- We do **not** use customer prompts/completions to train foundation models.
- We do **not** provide a general-purpose PII redaction layer inside the Hosted API (customers should redact/tokenize client-side if needed).

# Hosted API
## Retention behavior
- Hosted retains **operational metadata** for analytics and reliability monitoring.
- Hosted may retain **payload/content** in the debug capture store for a limited period to support troubleshooting and abuse prevention.

## Access controls
- Access to debug capture is limited to a small on-call group (Support/SRE) and is audited.
- Payload access is only for investigating a specific incident or customer escalation.

## Important limitation (common enterprise question)
- **Hosted API cannot guarantee "no logging" / "zero retention" of payloads** today. Even if sampling is reduced, we may still capture payloads under error/abuse heuristics.

# Dedicated
- Dedicated is operated by Redwood but provides stronger isolation. Retention and debug capture options may be customized by contract, but it is not equivalent to customer-owned logging unless explicitly implemented.

# Private (VPC / on-prem)
- Private deployments can be configured so that payload/content does not enter Redwood shared systems.
- The customer controls network boundaries and can integrate customer-managed logging and KMS.
- If a customer requires "no content at rest" (payloads never written to disk), Private is the recommended option, subject to the customers chosen observability configuration.

# Customer-facing summary (approved language)
- Redwood does not train on customer prompts/completions.
- Redwood retains operational metadata for reliability and billing.
- For the Hosted API, Redwood retains request/response payloads for a limited period for troubleshooting and abuse prevention with restricted access controls.
- A strict "no logging / zero retention" mode for Hosted API payloads is **not currently available**. Customers with this requirement should evaluate Redwood Private.
