Economics and SLOs Optimization Roadmap — Q2 2027

Summary
-------
This document describes the Q2 2027 roadmap for the Economics & SLOs Optimization initiative: a coordinated product and engineering program to reduce per-token inference cost, make SLOs more transparent and actionable for customers, and provide bundled pricing changes that align economic controls with reliability guarantees. It combines a short PRD, high-level design notes, pricing and packaging considerations, release plan, and an operational rollout playbook.

Background and motivation
-------------------------
- Customers have asked for clearer cost controls that do not force sacrificing latency SLOs.
- Internal telemetry shows 14% of hosted requests experience tail latency > target for routes with high token churn, leading to missed SLOs and increased incident work.
- Current pricing is per-token with optional reserved capacity; customers report difficulty estimating costs when autoscaling and when using cache/batching features.

Goals & success metrics (Q2 goals)
----------------------------------
Primary goals (deliverables):
1. Launch an "Economics Assistant" recommendation surface in the Console to propose batching + prefix caching + quantization profiles for tenant workloads.
2. Introduce SLO-tiered pricing bundles with explicit cost/SLO tradeoffs and a clear billing simulation tool.
3. Ship server-side adaptive batching thresholds and a fallback route that drops to cheaper-compatible model variants on overload.

Success metrics (target by EOW Q2 2027):
- 20% reduction in average per-token cost for participating tenants (measured net of reserved credits).
- SLO compliance improvement: reduce P99 token latency violations by 50% for opt-in routes.
- 35% of high-volume tenants adopt at least one recommended Economics Assistant suggestion within 30 days of availability.

Scope (in-scope / out-of-scope)
------------------------------
In-scope:
- Console recommendations UI and API surface for suggestions.
- Runtime changes: adaptive batching, model-variant fallback routing, dynamic cache TTLs.
- Pricing bundles: SLO-tiered bundles + billing simulation in Console.
- Metrics, dashboards, and alerting for rollout.

Out-of-scope (this quarter):
- On-prem installer changes for private deployments (will be tracked in eng-private-deployments).
- New model quantization algorithms (research will provide profiles only).

Product Requirements (high-level PRD)
------------------------------------
1) Economics Assistant (Console + API)
- Provide 3 ranked recommendations per tenant route: (a) Batching window adjustment, (b) Prefix/KV cache enablement & TTL, (c) Suggested quantization profile.
- Each recommendation includes estimated monthly cost delta, estimated SLO impact (latency delta at p50/p95/p99), and a confidence score.
- API: /v1/tenants/{tenant_id}/economics-recommendations returns JSON with suggestions.
- Owner: product -> Marina Quintero; eng -> optimizer-service team.

2) SLO-tiered pricing bundles
- Define three bundles: Bronze (cost-first), Silver (balanced), Gold (latency-first).
- Each bundle guarantees a different P99 token latency SLO for a route at a given committed capacity level.
- Bundles must be simulatable in Console using an uploaded workload sample or a sampled 24-hour trace.
- Billing change: new line-item labeling for SLO-bundles (e.g., SLO-BUNDLE:gold:route-123).
- Owner: pricing & revenue ops -> finance-and-legal (product to define tiers).

3) Runtime adaptive controls
- Adaptive batching: runtime must measure request size distribution and dynamically set batching window (min=2ms, max=40ms) to meet latencies for Gold/Silver bundles.
- Fallback routing: when queue depth > threshold (configurable per-tenant), route to compatible quantized variant (e.g., 8-bit) or to a lower-cost region.
- Cache TTLs: support per-tenant route TTLs for prefix cache with automatic eviction on model or prompt template changes.
- Owner: eng-serving-runtime -> kernel-and-scheduling and route-engine subteams.

Design specification (high-level)
--------------------------------
Architecture components involved:
- optimizer-service (new microservice): computes recommendations by synthesizing historical traces, cost model, and perf profiles.
- route-engine (existing): will apply adaptive batching and fallback routing policies at request ingress.
- cost-mapper (billing integration): adds SLO-bundle metadata to invoices and exposes simulation API.

Recommendation algorithm (summary):
- Input: 7-day sampled traffic trace (route, tokens_in, tokens_out, latency percentiles, model_id).
- Steps: 1) compute candidate batching windows and simulate token-latency curves using perf profiles; 2) estimate cache hit rates via prefix overlap heuristics; 3) compute cost delta for quantized model variants using per-token cost coefficients.
- Output: top-3 ranked suggestions with delta estimates and recommended rollout safety gates.

Pricing and packaging impacts
-----------------------------
- The SLO-tiered bundles introduce a new pricing dimension that combines committed capacity with SLO guarantees.
- Initial price points (draft):
  - Bronze: baseline per-token price (no latency guarantee).
  - Silver: +15% per-token over baseline for P99 <= 450ms at committed capacity.
  - Gold: +40% per-token over baseline for P99 <= 250ms at committed capacity.
- Bundles include an SLA credit schedule tied to SLO violations (credit up to 5% of monthly committed spend for Silver, up to 10% for Gold).
- Billing simulation: allow customers to run a 7-day simulation and view projected monthly spend and expected SLO compliance.

Operational rollout & monitoring playbook
----------------------------------------
1) Staged rollout:
   a) Internal canary: 3 internal tenants with representative workloads (date target: 2027-03-01).
   b) Beta cohort: opt-in customer list (15 customers) for 6 weeks.
   c) General availability: after successful beta (target 2027-05-15).
2) Monitoring and dashboards:
   - New dashboard: "Economics Assistant Adoption" (adoption %, accepted suggestions, estimated savings).
   - SLO dashboards per-bundle: P50/P95/P99 latency, queue lengths, fallback activation count, cache hit ratio.
   - Alerts: page on >3% sustained increase in p99 for Gold routes over 10 minutes or >15% delta between simulated and actual cost.
3) Rollback criteria:
   - If Gold P99 violations increase by >10% for 2 consecutive 1-hour windows in canary, rollback changes and reopen gating.

Open design questions and risks
------------------------------
- Measurement fidelity: simulated latency curves depend on accurate perf profiles; mismatch could lead to degraded customer experience.
- Quality regression risk with quantized fallbacks: must ship automatic quality monitoring and canary evaluation (prompt-set based).
- Contract/legal: bundle SLA language requires legal review for credit terms.

Appendix A: Example rollout checklist (for an opt-in tenant)
---------------------------------------------------------
1. Collect 7-day sample trace from tenant (route, model, tokens).
2. Run Console simulation and present recommended bundle and savings.
3. If tenant accepts: deploy recommendations to a canary route (10% traffic).
4. Monitor p50/p95/p99 and quality evals for 72hrs.
5. Gradually increase to 100% over 72hrs if metrics OK; otherwise rollback.
