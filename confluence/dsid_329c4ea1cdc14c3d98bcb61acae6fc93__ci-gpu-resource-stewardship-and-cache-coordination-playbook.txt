CI GPU Resource Stewardship and Cache Coordination Playbook

Summary
-------
This playbook defines the operational model, IaC patterns, and CI pipeline conventions we use to steward GPU resources in our CI/CD systems while maximizing cache hit rates across build artifacts and model artifacts. It describes ownership boundaries, SLOs, Terraform/IaC modules to reuse, and step-by-step recovery/runbook actions for the most common classes of failures. The guidance applies to Buildkite-based CI, ephemeral GPU pools used for evaluations, and the artifact caching/reuse systems (S3 object caches, signed content-addressable caches, and Redis-backed leases).

Scope
-----
- Applies to: CI pipelines that spawn GPU instances for unit/eval/integration jobs, ephemeral eval farms, and snapshot-based model build flows.
- Excludes: production serving fleets, long-lived Dedicated customer clusters (see eng-infra/gpu-fleet-and-capacity docs).

Goals and measurable SLOs
------------------------
- CI pipeline median job duration (GPU eval jobs): ≤ 12 minutes (measured per pipeline).
- Cache hit rate for model artifacts (8GB+ blobs): ≥ 85% for repeat-eval workflows.
- Job warmup failures due to missing caches or mounts: < 1% of GPU CI jobs per week.
- Artifact upload latency to primary cache (S3 multi-part + invalidation): p95 < 18s.

Components and responsibilities
-------------------------------
- GPU provisioner (service: gpu-provisioner): allocates cloud instances from heterogeneous pools (on-demand, spot, preemptible). Responsible for node bootstrapping and attaching EBS/attached NVMe where required. Owner: eng-infra (ci-cd).
- Lease manager (module: gpu-lease-ledger): records allocation tokens, enforces per-team quotas and preemption policies. Owner: eng-infra (gpu-fleet).
- Cache index (service: cache-index): Redis instances with TTL-based entries pointing to S3 object digests. Owner: eng-infra (ci-cd).
- Artifact store: S3 bucket with object lock and lifecycle rules for CI artifacts. Owner: infra-storage.
- Buildkite plugin: buildkite-gpu-cache-plugin (repo: infra/buildkite-plugins) — standardizes prefetch/upload and lock acquisition. Owner: dx-engineering.

Terraform / IaC modules (approved)
----------------------------------
Use these modules from the IaC registry to ensure consistent behavior and observability:
1. module/gpu-provisioner-v2: creates autoscaling groups, nodepool labels, and IAM roles. Required variables: allowed_spot_types, warm_pool_size, bootstrap_userdata_s3_path.
2. module/content-addressable-cache: S3 + KMS encryption + lifecycle; outputs bucket_name, cache_root_prefix, signed_url_service_role.
3. module/redis-cluster-small: 3-node Redis cluster with multi-AZ and auth.
4. module/gpu-lease-ledger: DynamoDB + lambda reconciliation + push metrics.

CI pipeline conventions (Buildkite)
----------------------------------
- Use the shared plugin: infra/buildkite-plugins#gpu-cache-plugin@v2.1. It provides steps: acquire-lease, prefetch-cache, run, upload-cache, release-lease.
- Each GPU job must include a unique cache-key computed as: sha256(repo@commit|dockerimage|dataset-version). Example: cache-key: sha256:abc123.
- Prefetch strategy: first check Redis index for object digest; if present, request signed URL for s3://bucket/digest and stream into local NVMe (concurrent download with 4 streams).
- Upload strategy: content-addressable — upload to temp prefix (uploads/), then atomically copy-to-digest and update Redis index via signed service API.

Example Buildkite snippet (text)
--------------------------------
steps:
  - label: "Run GPU eval"
    plugins:
      - docker#v3.7.0:
          image: "gcr.io/redwood/ci-gpu:latest"
      - infra/gpu-cache-plugin#v2.1:
          cache_key: "${BUILDKITE_COMMIT}-${CI_DOCKER_IMAGE}-${DATASET_TAG}"
          prefetch_threads: 4
          upload_compression: zstd
    command: |
      set -euo pipefail
      /usr/local/bin/run-eval --model $MODEL --out results.json

Operational runbook: common incidents
-------------------------------------
1) Job stalls during prefetch (cache miss or slow network)
   - Detect: CI job log shows "waiting for cache" > 60s and download throughput < 5 MB/s.
   - Mitigation: Abort prefetch after 90s and fall back to streaming-from-S3 (non-prefetch mode).
   - Long-term fix: Add prefetch parallelism, verify Redis TTLs, and check cross-region S3 access.

2) Lease acquisition fails (quota exhausted)
   - Detect: buildkite logs show "lease denied: quota-exceeded" and metrics show gpu_lease_denied/sec > 0.
   - Troubleshoot:
     a) Check gpu-lease-ledger dashboard (DynamoDB consumed capacity, errors).
     b) Evaluate recent allocations: /api/v1/leases?team=...
   - Remediation: increase warm_pool_size for that team using the terraform module (see quick change below) or temporarily reassign idle warm nodes.

3) GPU nodes fail bootstrap (missing mount, kernel mismatch)
   - Detect: agent never registers or shows repeated kernel oops in cloud-init logs.
   - Steps:
     1. ssh into the node using bastion: ssh -i /keys/ci-bastion ubuntu@<ip>
     2. tail /var/log/cloud-init-output.log and /var/log/syslog
     3. If docker runtime missing: run /usr/local/bin/bootstrap-step.sh
   - Rollback: scale down ASG and replace problematic AMI. Create an AMI promotion ticket and follow image promotion playbook.

Quick IaC fixes (commands)
--------------------------
- Increase warm pool size (terraform):
  cd infra/modules/gpu-provisioner-v2/examples/production\  terraform apply -var='warm_pool_size=6'
- Force reconciliation for lease ledger:
  aws lambda invoke --function-name gpu-lease-ledger-reconcile /tmp/resp.json && cat /tmp/resp.json

Metrics and dashboards to monitor
--------------------------------
- gpu_ci_job_latency_seconds (histogram): pipeline-level median & p95.
- gpu_cache_hit_ratio (gauge): per-pipeline and global. Alert if < 80% for 6h.
- gpu_lease_denied_total (counter): alert if rate > 5/min sustained.
- s3_put_latency_ms (p95): alert if > 2500ms.
- buildkite_agent_registration_failures: alert if spike > 10/min.

Alerting thresholds (example)
----------------------------
- Critical: gpu_ci_job_latency p95 > 30m for > 15 minutes 
- Warning: cache_hit_ratio < 75% for > 1 hour
- Sev2: lease_denied_rate > 10/min for > 10 minutes

Ownership and escalation
------------------------
- First responder: eng-infra (ci-cd team) on pages for CI incidents.
- Secondary: eng-infra (gpu-fleet) — for capacity and preemption issues.
- Pager rotation: refer to oncall schedule in /confluence/eng-infra/oncall.md
- Escalation steps: if incident persists > 30m, page eng-sre and product-impact team.

Testing and rollout checklist for changes
----------------------------------------
1. Terraform plan reviewed and approved in stage.
2. Canary: apply change to staging with a 10% warm_pool delta and run 200 synthetic CI jobs.
3. Validate metrics: cache hit-rate, job median latency, and S3 put latency.
4. Promote to prod with rollout window and rollback plan.

Appendix A — recommended cache headers and lifecycle (table)
-----------------------------------------------------------
- Content type: application/octet-stream
- Cache-Control: max-age=31536000,immutable for digest objects
- Lifecycle rules: move uploads/ and temp/ to cold storage after 7 days, delete unreferenced objects after 90 days

Appendix C — maintenance windows and safe times
------------------------------------------------
- Weekly maintenance window for CI infra: Saturdays 03:00-05:00 UTC (minor interruptions permitted).
- Large IaC changes (> warm_pool_size delta 50% or IAM changes): schedule owner-approved maintenance window and notify product teams 72h in advance.
