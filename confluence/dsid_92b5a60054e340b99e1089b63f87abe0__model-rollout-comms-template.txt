Model rollout communications template (status page + customer messaging)

# Purpose
This page provides guidance and templates for external communications when performing **Hosted API model rollouts**, especially when **automatic fallback** is enabled and customer-visible behavior may become inconsistent.

# When to communicate externally
In general, do not create status page updates for routine canary rollouts that remain within SLOs. Communicate externally when:
- there is a sustained SLO impact (availability or latency)
- fallback is serving a substantial portion of traffic and user experience may change
- a rollback occurs due to customer impact
- an enterprise customer requires proactive notice per contract

# Channels
- **Status page**: used for broad incidents or notable degradations
- **Customer email**: used for enterprise accounts or customer-specific pins
- **Support macros**: used for inbound tickets referencing the rollout

# Status page template (degradation during rollout)
Title: Hosted API performance degradation

Body:
We are investigating increased error rates and latency for a subset of Hosted API requests. Some traffic may be served via fallback routes while we stabilize the system. We will provide another update within 30 minutes.

Next update: <time>

# Status page template (rollback completed)
Title: Hosted API mitigation applied

Body:
We have rolled back a recent model change and service metrics are returning to normal. We will continue monitoring and will publish a post-incident summary if warranted.

# Customer email template (enterprise pinned route)
Subject: Update on model rollout for your Hosted API route

Hello <Customer>,
We are performing a controlled rollout of a new model version for your route. During the rollout window, some requests may be served by a fallback model to maintain reliability. If you observe unexpected output changes, please reply to this email with example request IDs so we can investigate quickly.

Thank you,
Redwood Support

# Internal checklist before sending
- Confirm current state: ramp paused? rollback in progress?
- Confirm whether fallback share is elevated and why
- Align with Support on wording (avoid overpromising timelines)
- Ensure timestamps and next update commitments are realistic
