VPC namespace egress policing and tenant isolation pattern

Summary:
This page defines the VPC namespace pattern used across Redwood Inference for logical tenant isolation inside shared VPCs, combined with an egress-policing layer and emergency VPN fallback. The intent is to enable self-service tenant onboarding, predictable egress controls for compliance, and rapid isolation during incidents without requiring per-tenant VPCs in every account.

Goals:
- Provide strong lateral isolation between tenants while minimizing account proliferation and VPC sprawl.
- Enforce auditable egress policies (allow-lists, TLS inspection points, and destination logging).
- Offer an automated, Terraform-driven onboarding flow that integrates with IAM, DNS, and network firewalls.
- Support an emergency VPN fallback path for tenants to redirect traffic to a quarantine VPC for investigation.

Out of scope:
- This pattern does not replace Private (on-prem) deployments where customers require dedicated physical networks.
- Does not prescribe application-level auth or secret management beyond network controls.

Key concepts and terminology:
- VPC namespace: a logical namespace represented by a subnet + tag-set + route-table configuration inside a shared VPC owned by the platform account. Each tenant receives zero or more namespaces.
- Egress policing: network-level controls (Network Firewall, Firewall Manager, or VPC Service Controls) that gate outbound destinations per-namespace.
- Quarantine VPC (quarantine-vpc): a central, audited VPC where suspicious tenant traffic can be routed for inspection and remediation.
- Namespace controller: a controller/service that reconciles Terraform module outputs and applies tag-based network policies and DNS ownership.

Pattern overview:
1) Namespace provisioning (self-service):
- Customer or internal tenant provisioning creates a Tenant CR via the onboarding service (API or internal console).
- The onboarding service runs a Terraform module (tenant-vpc-namespace) in a platform pipeline to create: subnet(s), NAT (optional), route table, security group placeholders, DNS zone entry, and tags: {redwood:tenant, namespace:id}.
- The module outputs a namespace id, CIDR, route table id, and private hosted zone.

2) Egress policing placement:
- All namespace outbound traffic flows through one of two enforced paths depending on policy:
  a) Egress gateway (AWS Network Firewall or Transit Gateway inspection filter) for high-compliance tenants.
  b) Shared NAT + Firewall Manager rules for lower-compliance tenants.
- Policies are declared as hierarchical rules: global allowlist, tenant deny overrides, and per-namespace exceptions.

3) Emergency VPN fallback:
- Each namespace includes a route-table flag that can be toggled by the namespace controller to redirect 0.0.0.0/0 to the quarantine-vpc via Transit Gateway attachments and static route overrides.
- When enabled, egress is forced into the quarantine VPC where additional inspection tooling (packet capture, decrypted TLS proxies under legal process, or IDS) runs.

Security and compliance controls:
- All egress decisions are logged to the central network-telemetry topic (Kinesis/CloudWatch/NetworkObservability) with tenant_id, namespace_id, dest_ip, dest_port, action, and rule_id.
- KMS keys used by NAT/inspection services are customer-scope (platform-managed KMS with CMKs per-region). Key access is controlled via IAM roles bound to the namespace controller.
- Firewall rule changes require a signed PR in Git (Terraform) and automated policy tests in CI before merge for restricted tenants.

Terraform module contract (tenant-vpc-namespace):
- Inputs (required): tenant_id, namespace_name, requested_cidr, compliance_tier (low/standard/high), preferred_azs (list).
- Outputs: namespace_id, subnet_ids (list), route_table_id, nat_gateway_id (optional), hosted_zone_id.

Sample module usage (striped YAML for readability):
```
module "tenant_namespace" {
  source           = "git::ssh://git@internal.redwood/repo/terraform-modules//tenant-vpc-namespace"
  tenant_id        = "t-12345"
  namespace_name   = "batch-workers"
  requested_cidr   = "10.50.12.0/24"
  compliance_tier  = "standard"
  preferred_azs    = ["us-west-2a","us-west-2b"]
}
```

Configuration table (policy defaults):
| Setting | Default | Notes |
|---|---:|---|
| compliance_tier | standard | high tenants require egress gateway + deep inspection |
| global_allowlist | [cloud-dns, metrics, auth] | maintained in central repo |
| quarantine_vpc_cidr | 172.31.240.0/20 | reserved for incident handling |

Implementation steps (operational procedure):
1) Prepare platform pipeline: create a Git-backed Terraform workspace per-tenant with policy-as-code gates (policy checks run by Conftest/OPA).
2) Deploy tenant-vpc-namespace module with dry-run and a policy report.
3) Namespace controller picks up outputs and applies tag-based Firewall Manager rule assignments.
4) Create private hosted zone delegation and issue TLS certs via cert-manager or ACM.
5) Run integration tests: internal egress probes to known destinations to validate allow/deny.
6) Mark namespace as active and notify tenant owner.

Rollout considerations and canary strategy:
- Canary 1: Onboard 3 low-impact tenants with monitoring hooks. Verify logs and billing.
- Canary 2: Expand to 10 tenants across two regions and enable per-namespace emergency toggle.
- Full rollout: Enable automation for self-service creation and removal with audit trail retention set per policy.

Monitoring, metrics, and alerts:
- Metrics to emit per-namespace: egress_bytes_total, denied_connections_count, allowlist_hits, quarantine_routes_applied.
- Alerts (examples):
  - P1: denied_connections_count > 1000 across 5 minutes for a high-compliance tenant -> Pager + auto-quarantine.
  - P2: namespace_controller_apply_failures >= 5 -> Slack #infra-ops and oncall.
- Dashboards: per-tenant egress heatmap, top denied destinations, rule-change timeline.

Failure modes and mitigations:
- Misconfigured allowlist accidentally blocks telemetry: have a read-only emergency bypass route to platform metrics collectors and a documented rollback playbook.
- Terraform drift causes overlapping CIDRs: namespace controller rejects outputs with overlapping_cidr flag and opens an incident ticket.
- Transit Gateway quota exhaustion: fall back to per-region NAT with mitigations in the capacity runbook.

Runbook: quick isolate a namespace (operator steps):
1) Identify namespace_id and tenant owner.
2) From the namespace controller UI/CLI: set quarantine=true which applies the route override.
3) Confirm route propagated in Transit Gateway (aws ec2 describe-transit-gateway-route-tables).
4) Enable packet capture in quarantine VPC and attach forensic workspace.
5) If malicious, revoke tenant IAM role sessions and disable namespace at application layer.

Ownership and SLAs:
- Ownership: Network Platform team (primary), Infra Security (review), Tenant Onboarding (consumer).
- SLOs: namespace_provision_time < 30 minutes (90th percentile), emergency_quarantine_apply < 2 minutes (99th percentile).

Appendix: CLI checks and snippets:
- Check route override (example):
  aws ec2 describe-route-tables --filters Name=tag:namespace-id,Values=t-12345 || true

- Revoke emergency route (example Terraform target remove):
  terraform apply -target=module.tenant_namespace.null_resource.route_override
