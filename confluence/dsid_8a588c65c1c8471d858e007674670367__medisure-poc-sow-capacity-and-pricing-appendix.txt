MediSure POC SOW Appendix: Capacity, Autoscaling, and Pricing (HIPAA Private)

h1. Purpose
This page is a one-page appendix template for the MediSure POC Statement of Work (SOW). It summarizes recommended reserved capacity, autoscaling/burst configuration, estimated monthly pricing, and HIPAA Private deployment security requirements.

h1. Traffic shape and sizing assumptions (customer-provided)
* Peak (bursty): ~900 requests/sec for a few minutes
* Sustained (95th): ~600 requests/sec
* Average generation: ~60 tokens/request (average per conversation/request for planning)
* Deployment: HIPAA Private (no multi-tenant)

Derived peak token rate:
* Peak tokens/sec = 60 tokens/request * 900 requests/sec = 54,000 tokens/sec

h1. Performance baseline used for sizing (internal reference)
Model/runtime reference point (current): *redwood-3-small (serving runtime 2.4, quantized)*
* Typical throughput at p95 latency targets: ~14,000 tokens/sec per GPU
* With aggressive quantization + KV caching (requires customer acceptance testing): up to ~17,000 tokens/sec per GPU

Notes:
* Cold start/kernel warm-up can add ~150–350 ms to tail latency if a burst arrives before preheat.
* Final sizing must be validated via smoke test with MediSure prompts/eval set.

h1. Capacity recommendation for SOW
We recommend presenting two commitment tiers; both assume a max burst limit and a preheat/runbook process.

h2. Option A (Standard): Recommended default
* Reserved GPUs: *4*
* Burst/autoscale cap: *7 GPUs max*
* Expected coverage: Handles 54k tokens/sec peak with headroom using the 14k tokens/sec/GPU baseline (54k/14k = 3.86 GPUs; reserve 4 for safety)
* Availability guidance: Distribute reserved GPUs across 3 AZs (e.g., 2/1/1) when supported by the customer VPC/subnet design.

h2. Option B (Lean): Cost-optimized (requires acceptance testing)
* Reserved GPUs: *3*
* Burst/autoscale cap: *6–7 GPUs max* (recommend 6 if strict cost control; 7 if strict latency)
* Dependency: Requires validated performance on MediSure eval set with KV caching + quantization optimizations and a successful preheat procedure.
* Risk statement: Higher probability of short-lived tail-latency spikes if bursts arrive outside preheat windows.

h1. Autoscaling and burst policy (SOW language-ready)
Recommended autoscale configuration:
* min_reserved: matches commitment (3 or 4)
* max: 7 (or 6 for Lean with cost constraint)

Scale-up triggers (aggressive):
1) Sustained request queue growth for >= 30 seconds, OR
2) GPU utilization > 75% for >= 30 seconds, OR
3) p95 end-to-end latency breaches the agreed target for 2 consecutive 30-second windows

Scale-down behavior (conservative):
* Cooldown: 3 minutes
* Do not scale below min_reserved

Preheat guidance:
* Preheat window: begin *10 minutes* before known business peaks and before planned demos.

h1. Preheat + acceptance checklist (onboarding milestone)
Run the following before go-live and before any scheduled high-traffic event:
# KV warm-up for top ~200 common prefixes (or customer-provided top intents)
# Bake kernels for seq_len 256 and 512
# Smoke load test: 5 minutes at ~300 RPS per GPU (or ~75% of expected steady state)
# Validate p95/p99 latency and token/sec throughput
# Capture KV hit rate snapshot and attach to onboarding ticket

Suggested acceptance criteria to include in SOW (edit to match negotiated SLA):
* Under sustained 600 RPS: p95 latency within target and no sustained queue growth
* Under 900 RPS burst (few minutes): no error-rate increase beyond agreed limit; p95 may degrade but remains within the negotiated burst target

h1. HIPAA Private deployment requirements (SOW bullets)
Minimum requirements:
* Private deployment (single-tenant). No shared multi-tenant serving for PHI.
* Signed BAA prior to production PHI.
* Customer-managed KMS for encryption keys (HSM recommended where available).
* Audit and access logging enabled; retention >= 1 year (or customer policy if longer).
* Principle of least privilege for operators; break-glass access must be logged and time-bounded.

Capacity/availability constraints for HIPAA:
* Use reserved/dedicated capacity for committed workloads.
* Do not use spot/preemptible instances for serving PHI workloads in production. (If customer requests non-prod cost reduction, document environment separation explicitly.)
* Recommend AZ spread to reduce single-AZ failure impact (example for 4 GPUs: 2/1/1 across three AZs).

h1. Pricing guidance (internal-to-SOW appendix numbers; update with current rate card)
Rates (most recent internal guidance):
* Reserved GPU seat: $3.25 per GPU-hour
* Burst credits (hourly equivalent when averaged for short spikes): $1.20 per GPU-hour

Monthly estimates (30-day month, 24x7):
* Standard (4 reserved GPUs): 4 * 24 * 30 * $3.25 = $9,360/month baseline
* Lean (3 reserved GPUs): 3 * 24 * 30 * $3.25 = $7,020/month baseline + burst variable

Example burst budget (illustrative):
* If bursting +3 GPUs for 2 hours/day on average: 3 * 2 * 30 * $1.20 = $216/month (burst)

Notes:
* Burst charges depend on realized usage and cap settings.
* Confirm final numbers with Finance/Legal before sending externally.
