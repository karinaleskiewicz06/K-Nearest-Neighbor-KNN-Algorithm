OpenAI-compat streaming truncation (missing [DONE]) - suspected gateway idle timeout

## Summary
We are tracking intermittent truncation of SSE streams on the OpenAI-compatible route (`/v1/chat/completions` with `stream=true`). The observed symptom is that clients receive some token events and then the connection closes without the terminal `[DONE]` event. Clients often see HTTP 200 with partial content.

This has been reported by multiple customers and correlates with a spike in client disconnect telemetry in **eu-west** (INC-2025-02-13-STREAM).

## Root cause hypothesis
The OpenAI-compat streaming stack can exhibit brief upstream quiet periods (no tokens emitted) during generation. When the upstream is quiet long enough, the API gateway/proxy may trigger a read/idle timeout and close the downstream connection, which appears to the client as a truncated SSE stream.

Contributing factors we suspect:
- OpenAI-compat uses HTTP/1.1 SSE with chunked transfer; some intermediaries are sensitive to idle gaps
- Current `proxy_read_timeout` for this route in eu-west is lower than we expect for long generations
- We do not currently emit heartbeat comments when the upstream is quiet

## Mitigation
### 1) SSE heartbeat comments
Emit an SSE comment line periodically when upstream is quiet to keep the connection active. Example payload (comment):
`: heartbeat

`

Proposed settings:
- heartbeat interval: 5s
- only when no downstream bytes have been sent in the interval

### 2) Gateway timeout tuning
Increase read timeout for OpenAI-compat streaming route in eu-west. (Coordinate with Eng Platform; see confluence://eng-platform/runbooks/api-gateway-timeouts.)

## Customer-facing guidance
Support/CS can recommend:
- Treat missing `[DONE]` as a failure and retry
- Capture `x-request-id`, region, and last SSE event for investigation

1. Canary heartbeat in eu-west for OpenAI-compat streaming only.
2. Bump gateway timeout in eu-west.
3. Expand to other regions after confirming disconnect rate decreases and no client parsing regressions.
