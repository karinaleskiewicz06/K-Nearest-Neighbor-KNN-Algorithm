provisioning-policy-emulator-and-cost-model

Overview

This page documents the Provisioning Policy Emulator (PPE) and associated cost model used to validate Terraform/IaC changes, capacity policies, and multi-pool routing before they hit production GPU pools. The emulator is intended for infra engineers, SRE, and platform product owners who need to reason about economic and SLO impacts of provisioning decisions.

Why this exists

- Reduce surprise spend from policy/IaC changes (new burst pools, altered preemptible ratios, network egress changes).
- Provide a deterministic, testable simulation that converts workload profiles into capacity allocations and cost projections.
- Gate Terraform changes in CI by asserting budget and SLO guardrails.

Scope and non-goals

- Scope: policy emulation for node types (GPU families), preemptible/spot mixing, warm-pool sizing, burst policies, and egress-billing assumptions.
- Non-goal: replace production scheduler behavior—the emulator is an analytic approximation used for policy validation, not for exact packet-level scheduling or placement decisions.

Key concepts

- Workload profile: time-series of request QPS, sequence-length distribution, and percentiles for tail latency tolerance.
- Provisioning policy: Terraform-driven configuration of pools, instance types, preemptible/commit ratio, and autoscaler parameters.
- Cost model: per-minute cost per instance (on-demand/spot), egress, storage, and auxiliary services (placement sidecars).
- Outcome KPIs: P95 latency impact, expected preemption rate, projected monthly run-rate, and 95th-percentile cost under stress.

Architecture and components

1) fleet-sim CLI (go/rust binary) — core emulator. Inputs: workload.json, policy.yaml, cost.yaml. Outputs: allocation_report.json, cost_projection.csv, and human-friendly summary.
2) Terraform plan adapter — small script that converts a planned Terraform change into a policy.yaml. Supports tfstate diff or plan JSON.
3) CI gate plugin — runs fleet-sim on proposed IaC changes; fails if assertions break.
4) Dashboard prototype — Grafana panel templates for cost burn and SLO delta comparisons.

Running a local simulation

Prereqs: fleet-sim binary (build instructions below), a sample workload profile, and a policy file.

Example commands:

1) Build (Linux / macOS):

   ./scripts/build-fleet-sim.sh

2) Run emulator with sample data:

   fleet-sim --workload samples/ecom-workload.json --policy samples/policy-small-burst.yaml --cost samples/cost-model.yaml --output ./out/alloc_report.json

3) Pretty-print summary:

   fleet-sim summarize ./out/alloc_report.json --format markdown > ./out/summary.md

What the emulator computes

- Node counts per pool to meet mean QPS and tail latency budget (heuristic model using per-GPU token throughput curves).
- Expected preemption events per day given preemptible ratios and historical spot-churn model.
- Egress and storage consumption across pools (based on per-request mb_out).
- Cost under steady, peak, and stress scenarios (95th percentile cost).
- SLO delta: projected P95 latency with and without proposed change.

Assertions and CI integration

We recommend the following gates in CI for Terraform changes touching pool or routing resources: 

1) Monthly run-rate delta < 20% (fail if projected monthly cost increases >20%).
2) P95 latency delta < 10% for primary workload (fail if greater).
3) Warm-pool reduction must not drop below 50% of historical warm usage.

Implementation in GitHub Actions (example):

- name: Run provisioning emulator
  run: |
    ./scripts/terraform-to-policy.sh plan.json > ci/policy.yaml
    fleet-sim --workload ci/smoke_workload.json --policy ci/policy.yaml --cost ci/cost.yaml --output ./ci/alloc.json || true
    fleet-sim assert ./ci/alloc.json --assert-file ci/assertions.yaml

Assertions file example (YAML):

- assertion: monthly_cost_delta_pct <= 20
- assertion: p95_latency_delta_ms <= 40
- assertion: warm_pool_min_ratio >= 0.5

Interpreting results

- allocation_report.json contains: total_nodes_by_pool (map), node_types_used (list), expected_preemptions, monthly_cost_breakdown (csv path), and simulated_latency_profile. Use fleet-sim summarize to generate human-readable notes.

Operational playbook (when simulation disagrees with prod)

1) If emulator projects large cost increase for a small Terraform tweak:
   a) Confirm policy.yaml conversion matches the plan (tf plan -> plan.json -> policy.yaml).
   b) Re-run with alternate workload profiles (stress, holiday, degraded-cache).
   c) Ask cost-model owner to review price assumptions (label: @finance-ops).

2) If emulator shows SLO regression > threshold:
   a) Run targeted latency microbenchmarks against a canary pool.
   b) Increase warm_pool size incrementally and re-simulate.
   c) Consider model-offloading to cheaper instance type for background requests.

Data sources and calibration

- Historical telemetry: token throughput by model family, observed GPU-hours/day, spot interruption logs.
- Calibration pipeline: nightly job that re-fits throughput curves using the previous 28 days.
- Where applicable, use A/B data from steady vs burst pools to refine preemption impact model.

Validation and limitations

- Validation: compare emulator projections to a rolling 7-day reconciliation against production spend and observed P95 delta. Track divergence metric; acceptable divergence <= 12% for cost and <= 8% for P95 latency.
- Limitations: does not model intra-node queuing granularity, PCIe/NIC contention, or complex multi-tenant interference beyond an aggregate noise model. Use cluster-level canaries for fine-grained verification.

Appendix A — Developer workflows

- Creating a new policy test: Duplicate samples/policy-template.yaml, edit pools, and add a sample workload under samples/. Run fleet-sim and commit new golden allocation files to tests/golden/.
- Updating cost assumptions: Update cost.yaml and add on PR a short justification and reference pricing link. Peer-review required by finance-ops.

Appendix B — Build and dev notes

- Build: repo/toolchain/ make build-fleet-sim (requires go 1.21, Rust 1.72 for native libs).
- Local dev: set ENV FLEET_SIM_CALIB_DIR=~/.fleet-sim/calib to point to calibration samples.
- Tests: unit tests validate the math; integration tests run a 2-hour simulated window in CI nightly (label: integ-sim-nightly).
