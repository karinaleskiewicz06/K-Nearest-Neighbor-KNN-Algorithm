GPU cost-center mapping, tagging standards, and Terraform IAM patterns

Overview

This page documents the standard patterns we use to map GPU resources to cost centers, required tagging and metadata conventions, and recommended Terraform/IaC IAM patterns to ensure billing, security, and automation work across hosted, dedicated, and private deployments. It applies to all GPU node pools, GPU host accounts, and Terraform modules that manage compute, networking, or billing exports.

Goals

- Ensure every GPU instance and related resources can be attributed to a business cost center for accurate chargebacks and forecasting.
- Provide a single canonical tagging and IAM pattern that is easy to validate in CI and enforce with policy tools (Sentinel/OPA/Cloud Custodian).
- Reduce manual reconciliation and minimize risk of orphaned costs.
- Keep tags and IAM scoped to least privilege while preserving automation needs for autoscalers, node pools, and billing exporters.

Scope

Applies to: GPU node instances, GPU instance templates, GPU autoscaler groups, GPU subnetworks, GPU provisioning pipelines, Terraform modules under sources/confluence/eng-infra/terraform-and-iac, and account-level billing export configuration. Exemptions must be approved by the infra cost-ops working group.

Tagging and Metadata Standards

Canonical tags (all keys are lowercase, kebab-case):

- cost-center: short code for the business group (e.g., ai-platform, search-ux, ads-recs)
- owner-email: mailing list or owner email for oncall and billing (e.g., ml-platform@redwood.com)
- project: product or project slug (e.g., realtime-summarization)
- environment: prod | staging | dev | test
- gpu-type: a100-80gb | a100-40gb | h100 | t4 | v100
- billing-code: internal accounting code (optional, for Finance mapping)
- deployment-mode: hosted | dedicated | private

Tagging rules and enforcement:

1) Required tags: cost-center, owner-email, project, environment, gpu-type, deployment-mode.
2) All tags must be applied at resource creation time via Terraform modules or the provisioning pipeline; tag mutation by human operators is discouraged.
3) Tag values must match the canonical registries: cost-center must be in the Cost Center Registry (see section below), environment must be one of the enumerated values.
4) CI validation: Terraform plan step must run a validator (terraform-validate-tags.sh) that rejects plans missing required tags.

Cost Center Registry

Maintain the registry as a small YAML file in the infra-config repository: infra-config/cost-centers.yml. Schema (example):

- code: ai-platform
  name: AI Platform
  finance_owner: ops-finance@redwood.com
  allowed_projects:
    - model-serving
    - eval-harness

Automation that reads this file is embedded in the Terraform module CI checks and in the billing ETL that maps exported usage to GL accounts.

Terraform and IAM Patterns

Principles

- Module-per-responsibility: compute modules (gpu-node-pool), network modules (gpu-subnet), and billing modules (billing-export) are separate with clear inputs for tags.
- Least privilege by role: runtime roles for kube nodes, CI deployer roles, and billing-exporter roles should be distinct.
- Use resource-level service accounts where cloud supports them (e.g., GCP service accounts per node pool).

Example module input interface (gpu-node-pool module)

- name (string)
- gpu_type (string)
- min_size (number)
- max_size (number)
- cost_center (string)
- owner_email (string)
- project (string)
- environment (string)
- tags (map) 

Example Terraform snippet (GCP)

```hcl
module "gpu_node_pool_x" {
  source     = "git::ssh://git@github.com/redwood/terraform-modules.git//gpu-node-pool"
  name       = "nlp-a100-80gb"
  gpu_type   = "a100-80gb"
  min_size   = 2
  max_size   = 20
  cost_center = "ai-platform"
  owner_email = "ml-platform@redwood.com"
  project    = "redwood-ml-prod"
  environment = "prod"
  tags = {
    billing-code = "R-ML-1001"
  }
}
```

IAM patterns (recommended roles)

- role/gpu-node-runner: permissions for kube node agent, limited to read/write for node metadata, attach/detach disks, and use GPUs.
- role/gpu-autoscaler: permissions to resize instance groups/node pools, but scoped to named node pools.
- role/billing-reader: read-only access to billing export and billing account metadata for Finance pipelines.
- role/billing-writer: permission to create BigQuery datasets and exports for billing (scoped to a central billing account).

Inline policy example (JSON, trimmed):

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["compute.instances.create", "compute.instances.delete"],
      "Resource": ["projects/redwood-*/zones/*/instances/*"],
      "Condition": {"StringEquals": {"resource.tags/cost-center": "ai-platform"}}
    }
  ]
}
```

CI/CD Integration and Policy Enforcement

1) Pre-commit hooks: linters that ensure tag keys and tag key order (optional) in module inputs.
2) Terraform plan step: run terraform-validate-tags.sh which verifies required tags exist and cost_center matches infra-config/cost-centers.yml. Exit non-zero on violation.
3) Policy checks: Open Policy Agent (rego) policies run in the pipeline to ensure no lifetime-freeing overrides of tags and that IAM roles do not use wildcard resource scopes.
4) Push-time enforcement: GitHub Actions workflow calls policy-checker, then terraform plan, then a plan review required by the owner_email listed in the plan summary for prod environments.

Enforcement examples (CI snippets)

- terraform-validate-tags.sh (simplified):

```bash
#!/usr/bin/env bash
set -euo pipefail
python3 tools/validate_tags.py --plan-file $TF_PLAN > /tmp/tag_errors || true
if [ -s /tmp/tag_errors ]; then
  cat /tmp/tag_errors
  exit 2
fi
```

- OPA rego example rule (pseudo):

```
package terraform.gpu

violation[res] {
  res := input.resources[_]
  resource_type := res.type
  resource_type == "google_compute_instance"
  not res.values.tags.cost-center
}
```

Billing export and mapping

- Central billing project: billing-redwood-prod (managed by Finance + Infra). Billing exports are BigQuery datasets owned by finance-billing@redwood.com.
- Per-account mapping job: nightly ETL joins exported usage with cost-centers.yml and sends reports to CostOps Slack channel and Finance.
- Near-real-time alerts: if any top-50 spenders have untagged spend > $500 in 24h, create a PagerDuty incident to cost-ops.

Operational Runbook (when untagged GPU spend is detected)

1) PagerDuty alert triggers CostOps on-call.
2) Run billing query (example):

```sql
SELECT resource_name, SUM(cost) as cost, ARRAY_AGG(DISTINCT IFNULL(tags, [])) as tags
FROM `billing-data.gcp_exports.*`
WHERE DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 1 DAY)
AND resource_type LIKE '%gpu%'
GROUP BY resource_name
ORDER BY cost DESC
LIMIT 50;
```

3) If resource is missing cost-center: find owning project and check owners via owner-email tag (if present). If owner-email is missing, escalate to infra-sre for the account.
4) Remediation steps: add tags via IaC if the resource was created by Terraform; if created outside IaC, create a ticket to reconcile and migrate resource to IaC-managed modules.

Ownership and SLAs

- CostOps team: maintain cost-centers.yml, run nightly ETL, first responder for billing anomalies.
- Infra module owners: maintain gpu-node-pool, gpu-subnet modules and ensure tag inputs exist.
- SLA for remediation of untagged top-50 spenders: 48 business hours for root cause + tagging or migration plan.

Migration and Rollout Plan for enforcing required tags on existing resources

1) Discovery: run inventory to identify untagged GPU resources and collect project/owner metadata.
2) Soft enforcement (30 days): pipeline adds warnings to PRs and CostOps daily digest.
3) CI rejection (60 days): terraform plan will fail in non-exempt projects until tags are supplied.
4) Hard enforcement (90 days): cloud policy will deny creation of untagged GPU resources in enforcement-target projects.

Table: enforcement timeline

- discovery-window: 0-14 days
- soft-enforce: 15-45 days
- ci-block: 46-75 days
- cloud-policy-block: 76+ days

Related operational notes and gotchas

- Spot/Preemptible instances: tagging still required, but short-lived instances may be automatically reaped; ensure autoscaler tags propagate.
- Cross-account VPCs: tags live on compute resources; network-level metadata should include a "peering-cost-center" tag where applicable.
- Private deployments: customers may enforce their own cost-center tags; map those to internal cost_center codes in the ETL layer.

Diagnostics and Useful Queries

- List GPU node pools missing required tags (gcloud CLI):

```bash
gcloud compute instances list --filter="labels.cost-center:*" --format="table(name,zone,labels)"
```

- BigQuery sample for daily untagged report (abbreviated):

```sql
SELECT project.id as project_id, ARRAY_AGG(DISTINCT resource.labels) as labels, SUM(cost) as cost
FROM `billing-data.gcp_exports.gcp_billing_export_v1_*`
WHERE JSON_EXTRACT_SCALAR(labels, '$.gpu-type') IS NOT NULL
AND JSON_EXTRACT_SCALAR(labels, '$.cost-center') IS NULL
GROUP BY project_id
ORDER BY cost DESC;
```

Appendix: Example module README snippet

- Enforce tags via variables and document which of the variables must be set by the caller. Example header:

"Required inputs: cost_center, owner_email, project, environment, gpu_type. Failure to provide these will cause the pipeline to fail."

- Example troubleshooting checklist:

1) Did terraform plan show the tags in the proposed change?
2) Are tags set at both instance and instance-template level?
3) Is the resource created via a third-party tool (kops, custom script) rather than Terraform?
4) If tags are missing in production, open incident and create a migration ticket.
