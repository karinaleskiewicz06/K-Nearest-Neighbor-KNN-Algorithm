Postmortem: SEV-2 Runtime kernel selection caused latency spike (2026-03-18)

A new kernel selection heuristic preferred a kernel variant that performed poorly for a specific sequence length distribution on A100s, causing latency regressions.
p95 latency increased by ~2.1x for a subset of long-context requests (8kk tokens) in eu-west. Error rate remained low (<0.3%), but SLO burn occurred.
15:12 UTC: SLO burn alert for eu-west chat long-context bucket fired.
15:20 UTC: On-call compared perf-canary data and saw regression after runtime build 2026.03.18.0.
15:33 UTC: Disabled new heuristic via feature flag; kernel selection reverted.
15:45 UTC: Latency returned near baseline; continued monitoring.
16:08 UTC: Incident resolved.
The heuristic used average sequence length rather than a percentile-based feature, leading it to select a kernel optimized for uniform 8k sequences. Real traffic had a bimodal distribution with heavy tail, making the choice suboptimal.
SLO burn alert and perf-canary comparison.
Feature-flag rollback of the heuristic and forced kernel selection to the prior stable variant for the affected pool.
Feature flags allowed rapid rollback without rebuild. Canary data provided quick correlation.
The heuristic change lacked traffic-representative validation for eu-west. Documentation did not specify the assumptions behind the new metric.
Update kernel selection model features to use p90 sequence length and tail weight (Serving Runtime; due 2026-04-10).
Add eu-west long-context perf-canary gating for runtime releases (Release Engineering; due 2026-04-01).
Document kernel selection assumptions and safe rollback steps (Serving Runtime; due 2026-04-05).
