Hosted API key rotation & revocation (customer guide)

# Overview
This page explains how to **regenerate (rotate)** and **disable (revoke)** a Redwood Hosted API key. Use these steps any time you suspect a key is exposed, you need to hand off ownership, or you want to follow a periodic rotation policy.

## Definitions
- **Rotate / regenerate:** create a new key and transition traffic from the old key to the new key.
- **Revoke / disable:** immediately invalidate an existing key so it can no longer authenticate.

## Where to manage keys
You can manage Hosted API keys in either:
- **Redwood Console** → *Settings* → *API Keys*
- **API (recommended for automation)**

## Rotate (regenerate) a key
### Option A: Console
1. Open **Console → Settings → API Keys**.
2. Select the key you want to rotate.
3. Click **Regenerate**.
4. Copy the new key value immediately (it is shown once).
5. Update your apps / CI secrets to use the new key.
6. Confirm requests succeed (200s) with the new key.
7. After validation, **disable** the old key (see Revocation below).

### Option B: API
- Create a replacement key: `POST /v1/api-keys`
- Optional: tag keys so you can identify them later (e.g., `name=prod-app-key-2025-05`)
- Once the new key is deployed, revoke the old key: `POST /v1/api-keys/{key_id}/revoke`

## Revoke (disable) a key
Revocation is immediate. Requests using a revoked key will receive **401 Unauthorized**.

### Console
1. Console → Settings → API Keys
2. Select key
3. Click **Disable**

### API
- `POST /v1/api-keys/{key_id}/revoke`

## Operational notes
- **Propagation:** console actions apply immediately, but allow up to ~60 seconds for all edge caches to reflect the new key metadata in rare cases.
- **Least privilege:** create separate keys per environment (dev/staging/prod) and per service.
- **Logging:** key usage events appear in Audit Logs (enterprise plans) and in the Usage dashboard.

## Troubleshooting
- Seeing 401s after rotation? Double check you did not paste the key ID instead of the key value.
- If you cannot see the key after creation, ensure you are in the correct org/project in Console.
