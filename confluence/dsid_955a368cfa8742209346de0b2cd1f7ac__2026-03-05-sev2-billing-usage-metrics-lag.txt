Postmortem: SEV-2 Usage metrics lag impacted billing exports (2026-03-05)

A backlog in the usage metrics pipeline caused downstream billing exports to lag behind real-time token usage.
Billing exports for a subset of enterprise contracts were delayed by up to 6 hours. No incorrect invoices were sent, but several Finance Ops workflows were blocked.
02:10 UTC: Automated job for hourly billing exports reported staleness >60 minutes.
02:20 UTC: Data Platform on-call engaged; identified increasing Kafka consumer lag.
03:05 UTC: Root cause traced to a schema change increasing message size and triggering slower deserialization.
03:30 UTC: Increased consumer resources and rolled back the schema change.
05:40 UTC: Backlog began clearing; staleness dropping.
06:35 UTC: Pipeline caught up; exports resumed on schedule.
A usage event schema change added an uncompressed prompt preview field which increased message size and CPU cost for consumers. Autoscaling thresholds were based on QPS, not processing time, so the consumer group did not scale fast enough.
Automated staleness check on billing exports.
Rolled back the schema change, temporarily increased consumer resources, and replayed affected partitions to ensure completeness.
Staleness check prevented incorrect exports. Replay tooling worked as intended.
Schema review did not consider downstream CPU impact; autoscaling policy was not aligned with processing latency.
Add schema-change checklist requiring downstream throughput impact assessment (Data Platform; due 2026-03-25).
Update consumer autoscaling to include processing time / lag slope (Data Platform; due 2026-04-05).
Move prompt preview field behind a separate topic for debug-only sampling (Data Platform; due 2026-04-15).
