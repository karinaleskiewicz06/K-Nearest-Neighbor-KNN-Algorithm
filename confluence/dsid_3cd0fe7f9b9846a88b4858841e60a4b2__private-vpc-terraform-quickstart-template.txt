Private VPC Terraform (Alpha) — Quickstart Template

## Overview
This page provides a copy/paste-friendly Terraform repo template for customers (or Redwood PS/SE) to create the foundational AWS networking footprint for a Redwood Private deployment.

Scope (alpha):
- VPC, subnets, routing, NAT defaults
- Security group patterns for private workloads
- VPC endpoints (interface + gateway) with private DNS options
- Flow logs with sane defaults + customer-owned destinations
- IAM scaffolding for running the Redwood Private installer (optional; customer IAM may be used instead)
- Optional placeholders/outputs to integrate with customer VPN/Direct Connect (no provider-specific routing encoded)

Non-goals:
- EKS cluster creation or application install. The cluster/app install is handled by the Redwood Private installer / Helm charts.

## Who should use this template
- Customer platform teams deploying Redwood Private in AWS (VPC-based)
- Redwood Solutions Engineering / Professional Services building POC environments
- Security teams reviewing default posture (endpoints, logging destinations, IAM boundaries)

## Prerequisites
- Terraform: 1.6+ (1.7+ recommended)
- AWS provider: pinned in `versions.tf` (see below)
- AWS account with permission to create: VPC, subnets, IGW/NAT, route tables, VPC endpoints, CloudWatch log groups (if using CW destination), IAM roles/policies (if using IAM scaffold)
- Decide upfront:
  - Region and 2–3 AZs
  - VPC CIDR (must not overlap with existing networks if VPN/DX planned)
  - Log destination ownership (customer-owned S3 bucket vs CloudWatch)

## Recommended repo layout
Use an environment-based layout (one state per environment). Avoid mixing multiple environments in a single state.

Directory tree:
- `README.md`
- `modules/` (optional; only if you add local wrapper modules)
- `envs/`
  - `dev/`
    - `backend.tf`
    - `main.tf`
    - `outputs.tf`
    - `providers.tf`
    - `variables.tf`
    - `versions.tf`
    - `terraform.tfvars.example`
  - `prod/` (same structure)
- `scripts/` (optional)
  - `tf.sh` (wrapper to standardize init/plan/apply)

Notes:
- `backend.tf` is intentionally environment-specific (S3 bucket, DynamoDB lock table, etc.).
- Keep `terraform.tfvars` out of source control for real environments. Commit only `terraform.tfvars.example`.

## Module sources and version pinning
Alpha modules move quickly; always pin exact versions (tags) for reproducibility.

Example module source pattern (Git tag):
- `source = "git::https://github.com/redwood-inference/redwood-terraform.git//modules/vpc?ref=v0.3.0-alpha.4"`

Guidance:
- For design partners: pin to the version recommended by Redwood PS/SE for your pilot.
- Do not use floating refs (e.g., `main`) in customer environments.

## Minimal template files (copy/paste)

### envs/dev/versions.tf
```hcl
terraform {
  required_version = ">= 1.6.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.50"
    }
  }
}
```

### envs/dev/providers.tf
```hcl
provider "aws" {
  region = var.aws_region

  default_tags {
    tags = var.tags
  }
}
```

### envs/dev/backend.tf (example)
Replace with your organization’s standard remote state.
```hcl
terraform {
  backend "s3" {
    bucket         = "<YOUR_TFSTATE_BUCKET>"
    key            = "redwood-private/dev/network/terraform.tfstate"
    region         = "<YOUR_TFSTATE_BUCKET_REGION>"
    dynamodb_table = "<YOUR_TFSTATE_LOCK_TABLE>"
    encrypt        = true
  }
}
```

```hcl
  type        = string
  default     = "cloudwatch"

  description = "CloudWatch retention (days) when flow_logs_destination=cloudwatch."
  type        = number

  description = "S3 bucket ARN when flow_logs_destination=s3 (customer-owned)."
  type        = string

  type        = map(string)
```

### envs/dev/main.tf
This composes the alpha modules with minimal inputs. Keep overrides explicit.

```hcl
locals {
  common_tags = merge(var.tags, {
    "redwood:component"   = "private-network"
    "redwood:env"         = var.name_prefix
    "redwood:managed-by"  = "terraform"
    "redwood:module-suite"= "redwood-terraform-vpc-alpha"
  })
}

module "vpc" {
  source = "git::https://github.com/redwood-inference/redwood-terraform.git//modules/vpc?ref=v0.3.0-alpha.4"

  name_prefix        = var.name_prefix
  vpc_cidr           = var.vpc_cidr
  aws_region         = var.aws_region
  az_count           = var.az_count
  enable_nat_gateway = var.enable_nat_gateway

  tags = local.common_tags
}

module "security_groups" {
  source = "git::https://github.com/redwood-inference/redwood-terraform.git//modules/security-groups?ref=v0.3.0-alpha.4"

  name_prefix = var.name_prefix
  vpc_id      = module.vpc.vpc_id

  # Opinionated defaults for private installs. Customize only with guidance.
  allow_private_egress_https = true

  tags = local.common_tags
}

module "endpoints" {
  source = "git::https://github.com/redwood-inference/redwood-terraform.git//modules/vpc-endpoints?ref=v0.3.0-alpha.4"

  enabled     = var.enable_vpc_endpoints
  name_prefix = var.name_prefix
  vpc_id      = module.vpc.vpc_id

  private_subnet_ids = module.vpc.private_subnet_ids

  # Endpoint security group: allow HTTPS from private subnets / node SGs.
  endpoint_security_group_id = module.security_groups.vpc_endpoints_sg_id

  # Defaults should include (at minimum) ECR API + DKR, S3 gateway, STS.
  # Redwood installer preflight will warn if required endpoints are missing.
  enable_private_dns = true

  tags = local.common_tags
}

module "flow_logs" {
  source = "git::https://github.com/redwood-inference/redwood-terraform.git//modules/flow-logs?ref=v0.3.0-alpha.4"

  enabled            = var.enable_flow_logs
  name_prefix        = var.name_prefix
  vpc_id             = module.vpc.vpc_id
  destination        = var.flow_logs_destination
  cw_retention_days  = var.flow_logs_retention_days
  s3_bucket_arn      = var.flow_logs_s3_bucket_arn

  tags = local.common_tags
}

module "iam_installer" {
  source = "git::https://github.com/redwood-inference/redwood-terraform.git//modules/iam-installer-role?ref=v0.3.0-alpha.4"

  # If installer_principal_arn is empty, the module should be skipped or create nothing.
  enabled                = var.installer_principal_arn != ""
  name_prefix            = var.name_prefix
  installer_principal_arn= var.installer_principal_arn
  permission_boundary_arn= var.permission_boundary_arn

  tags = local.common_tags
}

# Optional: VPN / DX placeholders (no resources; outputs + routing hooks)
module "private_connectivity" {
  source = "git::https://github.com/redwood-inference/redwood-terraform.git//modules/vpn-hooks?ref=v0.3.0-alpha.4"

  enabled     = false
  name_prefix = var.name_prefix
  vpc_id      = module.vpc.vpc_id

  private_route_table_ids = module.vpc.private_route_table_ids

  tags = local.common_tags
}
```

```hcl
  description = "Public subnet IDs (used for load balancers if applicable)."
}

output "cluster_node_security_group_id" {
  value       = module.security_groups.cluster_nodes_sg_id
  description = "Security group ID intended for cluster node ENIs."
}

  value       = module.endpoints.endpoint_ids
  description = "Map/list of created VPC endpoint IDs (used for verification)."
}

  value       = module.flow_logs.destination
  description = "Where flow logs are sent (cloudwatch|s3)."

}
```

### envs/dev/terraform.tfvars.example
```hcl
name_prefix = "acme-dev"
aws_region  = "us-east-1"

# Choose a non-overlapping CIDR (especially if VPN/DX will be used).
vpc_cidr = "10.30.0.0/16"

# 2 AZs is acceptable for early pilots; 3 AZs recommended for production.
az_count = 3

# NAT: enabled by default. If you disable NAT, ensure endpoints cover all required services.
enable_nat_gateway = true

# Endpoints: strongly recommended for Private to avoid public egress for AWS service access.
enable_vpc_endpoints = true

# Auditability
enable_flow_logs         = true
flow_logs_destination    = "cloudwatch"  # or "s3"
flow_logs_retention_days = 30
# flow_logs_s3_bucket_arn = "arn:aws:s3:::<CUSTOMER_AUDIT_LOGS_BUCKET>"

# Optional IAM scaffold (leave empty if customer will manage roles separately)
# installer_principal_arn  = "arn:aws:iam::<ACCOUNT_ID>:role/<CI_OR_ADMIN_ROLE>"
# permission_boundary_arn  = "arn:aws:iam::<ACCOUNT_ID>:policy/<PERMISSION_BOUNDARY_POLICY>"

tags = {
  "owner"       = "platform"
  "cost-center" = "private-deployments"
  "project"     = "redwood-private"
}
```

## How to run
From the environment directory (e.g., `envs/dev`):
1. `terraform fmt -recursive`
2. `terraform init`
3. `terraform validate`
4. `terraform plan -out tfplan`
5. `terraform apply tfplan`

Post-apply verification checklist:
- Confirm private subnets have a route to NAT (if enabled) and/or required endpoints exist.
- Confirm VPC endpoints show `Available` and private DNS is enabled where appropriate.
- If using CloudWatch destination for flow logs, confirm the log group exists and retention is set.

## Handoff to Redwood Private installer
You will typically need the following from Terraform outputs:
- `vpc_id`
- `private_subnet_ids`
- `public_subnet_ids` (if using public load balancers)
- `cluster_node_security_group_id`
- `installer_execution_role_arn` (if using the IAM scaffold)

Tip: capture outputs in a file for the installer step:
- `terraform output -json > tf-outputs.json`

The Redwood Private installer performs preflight checks and will warn on common misconfigurations (for example: missing ECR endpoints or private DNS issues).

## Customization guidance (supported extension points)
Safe, supported changes (typical):
- Adjust `az_count` between 2 and 3
- Change CIDR blocks (only before anything depends on them)
- Switch flow logs destination from CloudWatch to customer S3 bucket
- Disable/enable selected endpoints based on org policy (coordinate with Redwood; some are effectively required)

High-risk changes (coordinate with Redwood before changing):
- Replacing NAT architecture (single NAT, per-AZ NAT, or no NAT) after workloads are running
- Modifying route tables for private subnets that will host cluster nodes
- Disabling private DNS for endpoints used by the installer/runtime
- Adding restrictive security group egress without confirming all required service paths

## Common failure modes (what this template avoids)
- Installer cannot pull images: missing ECR endpoints or private DNS misconfigured.
- Intermittent DNS in private subnets: VPC resolver/forwarder assumptions, endpoint DNS settings, or split-horizon DNS conflicts.
- Unintended public egress: endpoints not present and NAT/IGW paths allow outbound traffic.
- Logging gaps: flow logs disabled or sent to a destination without retention/ownership clarity.
