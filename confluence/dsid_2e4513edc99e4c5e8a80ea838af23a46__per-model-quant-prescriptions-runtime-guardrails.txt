Per-model quant prescriptions & runtime guardrails (Model Catalog)

## Overview
This page defines how Redwood Inference publishes per-model default quantization recommendations ("quant prescriptions") in the Model Catalog, and how the runtime enforces safety guardrails with automatic fallbacks.

The intent is that developers can choose the catalog-recommended quantized variant (FP8 or INT8) with confidence that:
- Quantization has been calibrated against a fixed evaluation suite.
- The expected quality delta and uncertainty are recorded.
- Runtime will automatically route to a safer fallback (FP16/FP32) when guardrails indicate elevated regression risk.

This page supersedes earlier design notes and reflects the current field names and operational thresholds.

---

## What changed since the initial design
The initial ticket discussion used placeholder schema fields (e.g., `quant_prescription`, `quant_confidence_band`). The current Model Catalog schema uses the names below and slightly different semantics:
- `quant_defaults` (replaces `quant_prescription`): recommended profile(s) and the default selection.
- `calibration_artifacts_uri` (replaces `calibration_artifact_url`): immutable, versioned artifact location(s).
- `accuracy_guardrail` (replaces `quant_confidence_band`): guardrail envelope expressed as thresholds and uncertainty model.
- `fallback_policy` (replaces `fallback_chain`): explicit routing order and conditions.
- `customer_risk_tier` (replaces earlier "risk_tolerance" wording): `low | medium | high`.

Security note update:
- All calibration artifacts MUST be signed. Artifact ingestion rejects unsigned artifacts, and runtime only trusts signed artifacts.

## Definitions
### Quant profile
A quant profile defines the numerical format and any runtime knobs needed to serve the quantized model safely.
Common profiles:
- FP8 (e4m3fn / e5m2, depending on backend)
- INT8 (weight-only or W8A8 depending on kernel availability)

### Calibration artifact
A versioned bundle produced by calibration CI, typically including:
- scales / clip parameters
- histogram summaries
- calibration report (metrics, deltas, confidence)
- signature metadata

### Guardrail (accuracy_guardrail)
A policy envelope used by runtime to decide whether to serve the quantized variant or route to fallback. It combines:
- an expected accuracy delta vs FP16 baseline
- uncertainty bounds derived from evaluation variance
- hard stop conditions (e.g., missing artifacts, signature mismatch)

## Model Catalog schema (current)
Each model version MAY include multiple quantized variants. The catalog MUST publish one recommended default profile when a model is eligible.

### Required fields for a recommended quant default
- `quant_defaults`:
  - `default_profile`: one of `fp8` or `int8`
  - `eligible_profiles`: list of profiles tested (e.g., `fp8`, `int8`)
  - `customer_risk_tier_overrides`: optional mapping rules (described below)
- `calibration_artifacts_uri`: immutable URI(s) for each tested profile
- `accuracy_guardrail`:
  - `metric`: the primary metric used for gating (see Metrics section)
  - `max_expected_delta`: maximum allowed degradation vs FP16 baseline
  - `max_upper_bound_delta`: maximum allowed degradation at the upper confidence bound
  - `confidence_level`: currently 95%
- `fallback_policy`:
  - ordered list of variants to try (e.g., `int8 -> fp8 -> fp16`)
  - stop conditions that force immediate fallback

### Example (illustrative, not literal JSON)
For readability this is expressed as a schematic; refer to the model-catalog API docs for exact serialization:
- quant_defaults: default=FP8; eligible=[FP8, INT8]
- calibration_artifacts_uri: fp8=s3://model-calibration/.../fp8/; int8=s3://model-calibration/.../int8/
- accuracy_guardrail: metric="golden_suite_score"; max_expected_delta=-0.5%; max_upper_bound_delta=-1.0%; confidence_level=95%
- fallback_policy: [FP8, FP16]

## Calibration CI workflow
### When calibration runs
Calibration runs in CI when any of the following changes:
- new model version is onboarded
- quant kernel/backend version changes
- golden prompt suite version changes
- model maintainers request recalibration

### Evaluation suite
- Default suite size: 600 prompts (updated from earlier 300-prompt draft).
- Suites are versioned and stored in the eval harness.
- The suite is designed to be representative across core customer workloads.

### Outputs
For each (model_version, profile):
- accuracy delta vs FP16 baseline
- uncertainty estimate and 95% confidence bounds
- token-cost estimate (relative to FP16)
- latency estimate (p50/p95 when available)
- calibration artifacts, stored immutably with version tags

### Artifact signing
- Artifacts are signed at publish time using KMS.
- Ingestion rejects unsigned or improperly signed artifacts.
- Runtime treats signature verification failure as a hard stop and falls back immediately.

## Runtime guardrail behavior
### Decision flow (high level)
1. Resolve the requested model and determine the candidate quant profile:
   - If the customer specifies a profile explicitly, use it (subject to guardrails).
   - Otherwise default to the catalog `quant_defaults.default_profile`.
2. Verify prerequisites:
   - calibration artifacts exist and are signed
   - profile is eligible for this model version
3. Apply guardrails:
   - If `expected_delta` is below the configured limit AND `upper_bound_delta` is below its limit, serve quantized.
   - Else route according to `fallback_policy`.
4. Emit metrics and traces:
   - guardrail decision outcome
   - fallback rate
   - signature verification outcome

### Guardrail thresholds (current defaults)
Unless a model overrides thresholds, defaults are:
- confidence_level: 95%
- max_expected_delta: -0.5% (relative to FP16 baseline)
- max_upper_bound_delta: -1.0%

Interpretation:
- A model can have a small average regression, but the uncertainty band must not suggest a likely tail regression worse than -1.0%.

### Customer risk tiers
Risk tiers control how aggressively runtime chooses cheaper profiles:
- low: prefer FP8, avoid INT8 unless model explicitly certified; stricter thresholds may be applied per-account configuration.
- medium: default behavior (use catalog defaults).
- high: allow INT8 when eligible, as long as guardrails pass; still requires signed artifacts.

Note: risk tiers never bypass signature checks or hard stop conditions.

## Console / API surfacing
The Console surfaces, per model version:
- recommended profile (default)
- eligible profiles
- token-cost delta estimate vs FP16
- a safety badge:
  - "Recommended" when guardrails pass for default profile
  - "Caution" when the model is eligible but near thresholds
  - "Not recommended" when calibration fails or guardrails do not pass

The API surfaces the same information via model-catalog metadata fields described above.

## Operational runbook
### Recalibrating a model
1. Confirm the model version and target profiles (FP8, INT8).
2. Trigger the calibration CI job:
   - via the model onboarding pipeline, or
   - via the calibration harness workflow.
3. Validate results in the eval dashboard:
   - check delta vs FP16
   - confirm confidence bounds
   - verify token-cost estimate looks plausible
4. Confirm artifacts are published and signed.
5. Update Model Catalog metadata:
   - set/adjust `quant_defaults`
   - attach `calibration_artifacts_uri`
   - set `accuracy_guardrail` thresholds if the model requires overrides
   - define `fallback_policy`
6. Rollout:
   - stage validation with runtime guardrail metrics
   - production canary (recommended: 5% traffic) before full rollout

### Troubleshooting
- High fallback rate after rollout:
  - check if golden suite updated and model was not recalibrated
  - confirm runtime is reading the correct model-catalog version
  - verify signature verification success rate
- Missing artifacts:
  - ingestion likely failed; check CI publish step and KMS signing
- INT8 unexpectedly disabled:
  - confirm backend/kernel availability and that profile is listed in `eligible_profiles`

## Appendix: Hard stop conditions (always fallback)
Runtime must route to fallback immediately when:
- calibration artifacts are missing
- artifact signature is invalid or cannot be verified
- model-catalog metadata for quant defaults is malformed
- requested quant profile is not in `eligible_profiles`
