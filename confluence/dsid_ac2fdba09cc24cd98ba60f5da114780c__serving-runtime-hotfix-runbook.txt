Serving Runtime Hotfix Runbook (Emergency Patch Release)

h2. When to use this runbook
Use this runbook when a serving-runtime change must be shipped quickly to mitigate an active incident (typically Sev-1). This covers code change, build, validation, and handoff to rollout owners.

h2. Preconditions
* Emergency change approvals recorded per /policies-and-process/change-management/emergency-change-policy-v3
* Incident channel exists (or a dedicated Slack thread) with IC identified
* A rollback plan exists (previous runtime image tag + restart procedure)

h2. Step 1 — Cut a hotfix branch
1. Create branch naming: hotfix/runtime-<YYYYMMDD>-<short-issue>
2. Cherry-pick the minimum fix commit(s) only.
3. Update CHANGELOG entry under 'Runtime Hotfixes'.

h2. Step 2 — Create PR and get emergency reviews
1. Open GitHub PR targeting release branch (preferred) or main if release branch is not available.
2. Required reviewers: runtime on-call + SRE on-call (or IC).
3. Include in PR description: incident link, hypothesis, risk, rollback, rollout owners.

h2. Step 3 — Build + sign artifacts
Follow /eng-infra/ci-cd-and-build/hotfix-build-and-signing. Minimum artifacts:
* runtime container image (multi-arch if applicable)
* SBOM (CycloneDX)
* provenance attestation

h2. Step 4 — Validate the fix
*Minimum* validation required even in an incident:
* Unit tests for affected module
* One perf-canary run for representative model (e.g., Llama 3.1 70B)
* One stress test at the incident-triggering pattern (sequence length + concurrency)

Validation checklist (record results in PR):
* Error rate improves or eliminates the triggering error
* p95 latency does not regress > 10% compared to previous runtime image for the same workload
* No increase in OOM or GPU reset counters

h2. Step 5 — Prepare rollout notes
In the incident channel, post:
* New runtime image tag
* Expected impact during rollout (restarts, brief connection resets)
* Canary target (Hosted region or Dedicated cluster)
* Rollback criteria (metrics + customer symptom)

h2. Step 6 — Handoff to rollout owners
* Hosted: hand off to Platform/SRE per /eng-platform/runbooks/hosted-rollout-and-rollback-procedure
* Dedicated: hand off to Infra + CSEM per /eng-infra/gpu-fleet-and-capacity/dedicated-cluster-hotfix-rollout-notes

h2. Rollback reminder
If rollback triggers are met, roll back immediately; do not wait for a full incident update cadence. Announce rollback in incident channel and update status page wording to reflect mitigation change.

h2. Appendix — Common pitfalls
* Fix includes unrelated refactors (reject; keep minimal).
* No canary defined (must be explicitly waived by IC).
* Artifact unsigned or missing SBOM (must not ship).
