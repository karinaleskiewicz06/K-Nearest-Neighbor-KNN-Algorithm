SDK instrumentation for Quickstart templates (Python/TypeScript/Go)

## Summary
This page defines the recommended SDK instrumentation patterns used by Redwood Quickstart templates. The goal is a consistent, supportable signal set across languages while minimizing high-cardinality attributes and avoiding logging sensitive data.

**Applies to:** Template apps and SDK examples that call Redwood Inference endpoints (chat/generate, embeddings, rerank) and may also use retrieval + tool calling.

**Primary outcomes**
- Every request has: (1) a trace; (2) correlated logs; (3) standard span attributes; (4) a stable request ID surfaced to users.
- Streaming is resilient and observable (disconnects are measured and classified).
- Errors map to the template error taxonomy and are actionable in troubleshooting.

---

## Principles (what “good” looks like)
1. **Wrap the SDK client once** (at initialization), not at every call site.
2. **One top-level span per user request** (HTTP request, job, or CLI command) and one child span for each Redwood SDK call.
3. **Low-cardinality attributes only** on spans/metrics. Put high-cardinality details (e.g., prompt text) nowhere by default.
4. **Request correlation is mandatory:** Redwood request ID (from response headers) should appear in logs and in trace attributes.
5. **Redaction is on by default** for logs; templates must not emit prompts, tool outputs, retrieved chunks, or API keys unless explicitly enabled for local debugging.

---

## Standard span naming (cross-language)
Use the following span names across templates and SDK examples:

### Request-level spans
- `app.http_request` (for HTTP servers)
- `app.job` (for background workers)
- `app.cli` (for CLI commands)

### Redwood SDK spans
- `redwood.chat.completions` (OpenAI-compatible chat)
- `redwood.responses` (if using Responses-style APIs)
- `redwood.embeddings`
- `redwood.rerank`

### Template component spans (if present)
- `rag.retrieve`
- `rag.rerank` (if reranking)
- `agent.loop`
- `agent.tool.call` (one per tool invocation)

**Do not** create a span per streamed token/chunk. Record streaming as events/counters on the request span or the Redwood SDK span.

## Required span attributes (minimum viable)
Set these attributes on the *Redwood SDK span* when available.

| Attribute | Type | Example | Notes |
|---|---:|---|---|
| `ai.system` | string | `redwood` | Constant.
| `ai.operation` | string | `chat.completions` | One of: `chat.completions`, `responses`, `embeddings`, `rerank`.
| `ai.model` | string | `rw-llama-3.1-70b-instruct@2025-02-15` | Prefer pinned versions (include variant/version if available).
| `redwood.request_id` | string | `req_01J...` | Capture from response header; also add to logs.
| `http.status_code` | int | `200` | For HTTP-based SDKs.
| `error.type` | string | `auth_error` | From template error taxonomy (see below).
| `error.message` | string | `rate limit exceeded` | Keep short; no secrets.

### Recommended (if available without extra requests)
| Attribute | Type | Example | Notes |
|---|---:|---|---|
| `ai.input_tokens` | int | `1240` | If returned by API.
| `ai.output_tokens` | int | `312` | If returned by API.
| `ai.total_tokens` | int | `1552` | If returned by API.
| `redwood.region` | string | `us-west-2` | Low-cardinality.
| `redwood.deployment_mode` | string | `hosted` | One of: `hosted`, `dedicated`, `private`.
| `network.protocol` | string | `http` | Optional.

**Cardinality rules**
- Allowed: model name/version, deployment mode, region, template name/version, error type.
- Not allowed: user IDs, email, raw prompts, tool arguments, document IDs, URLs with query params, full stack traces as attributes.

## Log correlation (cross-language)
Templates must emit structured logs with the following fields where possible:
- `timestamp`
- `level`
- `message`
- `trace_id` / `span_id` (from OTel context)
- `redwood_request_id` (from response header)
- `error_type` (taxonomy)
- `template_name` and `template_version`

**Redaction defaults**
- Never log: `Authorization` headers, API keys, prompt text, retrieved chunk text, tool outputs, or full request/response bodies.
- If local debugging requires it, gate behind an explicit env var (e.g., `LOG_SENSITIVE_DEBUG=1`) and document it as unsafe for production.

---

## Error taxonomy mapping (SDK -> template)
All templates should map SDK/network exceptions into a consistent `error.type` (used in logs and spans). Recommended values:
- `auth_error` (401/403, missing key)
- `quota_error` (429 rate limit / quota)
- `timeout_error` (request or stream timed out)
- `network_error` (DNS, connection reset, TLS, proxy failures)
- `server_error` (5xx)
- `validation_error` (tool schema, structured output parsing)
- `retrieval_error` (retriever empty/failed)
- `tool_error` (tool execution failure)
- `unknown_error`

**Guideline:** keep the mapping logic in one place (a small helper module) so all call sites behave consistently.

---

## Streaming instrumentation guidance
Streaming introduces unique failure modes that must be observable:

**Recommended signals**
- Counter/log when a stream disconnect occurs: `stream.disconnect=1`
- Attribute or event capturing the phase: `stream.phase = start | mid | end`
- A “reconnect attempt count” integer (low cardinality): `stream.reconnect_attempts`

**Span events (preferred over attributes for per-attempt detail)**
- Event name: `stream.reconnect`
- Event attributes: `attempt`, `backoff_ms`, `reason` (keep `reason` from a small fixed set)

**Avoid**: emitting one span per reconnect attempt unless the SDK call is re-issued as a new request.

---

## Template telemetry tagging (adoption KPIs)
Templates may add a low-sensitivity tag to allow Redwood Console filtering of template-originated traffic.

**Rules**
- Must be **opt-in** and easy to disable (some proxies reject unknown headers).
- Must not include customer-identifying information.

**Recommended values**
- `template_name` (e.g., `rag-agent`)
- `template_version` (e.g., `1.2.0`)
- `template_language` (e.g., `python`, `typescript`, `go`)

**Do not include:** repo name, user handle, email, hostnames.

---

## Implementation pattern: “instrumented client wrapper”
The template should create one `InstrumentedRedwoodClient` (or equivalent) that:
1. Configures SDK defaults (timeouts, retries, backoff, streaming behavior).
2. Injects request metadata (template tags) if enabled.
3. Starts a span around each SDK call, sets required attributes, and records errors.
4. Extracts `redwood.request_id` from the response and stores it in:
   - span attribute `redwood.request_id`
   - a logger context field `redwood_request_id`

This wrapper should be the only place that understands:
- how to classify errors
- where to find request IDs
- how to attach OTel context

## Language-specific notes and examples

### Python (redwood-sdk-python)
**Recommended libraries**
- `opentelemetry-api`, `opentelemetry-sdk`
- `opentelemetry-instrumentation` for your web framework (FastAPI/Flask) if applicable
- Redwood SDK tracing helpers (see internal SDK changes: context propagation + request-id capture)

**Pattern**
- Use a module-level factory `get_client()` that returns a singleton instrumented client.
- Use `contextvars`-friendly logging so trace IDs are automatically correlated.

**Pseudo-code**
```py
from opentelemetry import trace

tracer = trace.get_tracer("quickstarts")

class InstrumentedRedwoodClient:
    def __init__(self, client, logger, template_tags=None):
        self._client = client
        self._logger = logger
        self._template_tags = template_tags or {}

    def chat(self, *, model, messages, timeout_s=None):
        with tracer.start_as_current_span("redwood.chat.completions") as span:
            span.set_attribute("ai.system", "redwood")
            span.set_attribute("ai.operation", "chat.completions")
            span.set_attribute("ai.model", model)

            try:
                resp = self._client.chat.completions.create(
                    model=model,
                    messages=messages,
                    timeout=timeout_s,
                    extra_headers=self._template_tags,  # opt-in
                )

                # capture request id if available
                req_id = getattr(resp, "redwood_request_id", None) or resp.headers.get("x-redwood-request-id")
                if req_id:
                    span.set_attribute("redwood.request_id", req_id)
                    self._logger = self._logger.bind(redwood_request_id=req_id)

                # tokens if available
                usage = getattr(resp, "usage", None)
                if usage:
                    span.set_attribute("ai.total_tokens", usage.total_tokens)

                return resp

            except Exception as e:
                error_type = classify_error(e)
                span.set_attribute("error.type", error_type)
                span.record_exception(e)
                span.set_status(trace.Status(trace.StatusCode.ERROR))
                self._logger.error("Redwood request failed", error_type=error_type)
                raise
```

**Python gotchas**
- Ensure timeouts are applied to both request setup and streaming reads.
- Do not attach full exception stack traces as span attributes; record exception via `record_exception()` only.

### TypeScript (redwood-sdk-typescript)
**Recommended libraries**
- `@opentelemetry/api`
- OTel SDK/auto-instrumentation depending on runtime (Node)
- Redwood TS SDK hooks/middleware for OTel-friendly integration

**Pattern**
- Implement a small wrapper that:
  - starts a span
  - calls the SDK
  - sets attributes
  - maps errors
  - captures request ID

**Pseudo-code**
```ts
import { trace, SpanStatusCode } from "@opentelemetry/api";

const tracer = trace.getTracer("quickstarts");

export class InstrumentedRedwoodClient {
  constructor(
    private client: any,
    private logger: any,
    private templateHeaders: Record<string, string> = {}
  ) {}

  async chatCompletions(params: { model: string; messages: any[] }) {
    return tracer.startActiveSpan("redwood.chat.completions", async (span) => {
      span.setAttribute("ai.system", "redwood");
      span.setAttribute("ai.operation", "chat.completions");
      span.setAttribute("ai.model", params.model);

      try {
        const resp = await this.client.chat.completions.create({
          ...params,
          headers: this.templateHeaders, // opt-in
        });

        const reqId = resp?.headers?.get?.("x-redwood-request-id") ?? resp?.requestId;
        if (reqId) {
          span.setAttribute("redwood.request_id", reqId);
          this.logger = this.logger.child({ redwood_request_id: reqId });
        }

        const usage = resp?.usage;
        if (usage?.total_tokens != null) {
          span.setAttribute("ai.total_tokens", usage.total_tokens);
        }

        return resp;
      } catch (err: any) {
        const errorType = classifyError(err);
        span.setAttribute("error.type", errorType);
        span.recordException(err);
        span.setStatus({ code: SpanStatusCode.ERROR });
        this.logger.error({ err, error_type: errorType }, "Redwood request failed");
        throw err;
      } finally {
        span.end();
      }
    });
  }
}
```

**TypeScript gotchas**
- Streaming: record disconnects/reconnect attempts as span events; avoid emitting per-chunk spans.
- If using `AsyncLocalStorage`, ensure your logger picks up trace context correctly.
- Some corporate proxies reject unknown headers; keep template telemetry tags opt-in and document how to disable.

### Go (redwood-sdk-go)
**Recommended libraries**
- `go.opentelemetry.io/otel`
- `go.opentelemetry.io/otel/trace`
- OTel HTTP instrumentation where appropriate (`otelhttp`) OR SDK-provided hooks

**Pattern**
- Pass `context.Context` everywhere.
- Start a span for each SDK call and attach attributes.
- Capture request ID from response headers and include it in logs.

**Pseudo-code**
```go
import (
  "context"
  "go.opentelemetry.io/otel"
  "go.opentelemetry.io/otel/attribute"
  "go.opentelemetry.io/otel/codes"
)

var tracer = otel.Tracer("quickstarts")

func (c *InstrumentedClient) ChatCompletions(ctx context.Context, model string, messages any) (any, error) {
  ctx, span := tracer.Start(ctx, "redwood.chat.completions")
  defer span.End()

  span.SetAttributes(
    attribute.String("ai.system", "redwood"),
    attribute.String("ai.operation", "chat.completions"),
    attribute.String("ai.model", model),
  )

  resp, err := c.sdk.ChatCompletions(ctx, model, messages, c.templateHeaders)
  if err != nil {
    errorType := ClassifyError(err)
    span.SetAttributes(attribute.String("error.type", errorType))
    span.RecordError(err)
    span.SetStatus(codes.Error, "redwood request failed")
    c.logger.Error("Redwood request failed", "error_type", errorType)
    return nil, err
  }

  reqID := resp.Header.Get("x-redwood-request-id")
  if reqID != "" {
    span.SetAttributes(attribute.String("redwood.request_id", reqID))
    c.logger = c.logger.With("redwood_request_id", reqID)
  }

  return resp, nil
}
```

**Go gotchas**
- Ensure the logger is context-aware or explicitly includes trace IDs.
- Avoid adding tool args/document IDs to span attributes (high cardinality).

## OTEL resource attributes (recommended)
Configure these once at service start:
- `service.name`: e.g., `redwood-quickstart-rag-agent`
- `service.version`: template app version (or git SHA in CI)
- `deployment.environment`: `local` | `staging` | `production`
- `redwood.template.name`: `rag-agent`
- `redwood.template.version`: `1.2.0`

---

## Local validation checklist (for template maintainers)
1. Run the app and confirm a trace appears for a single request.
2. Confirm logs include `trace_id` and a `redwood_request_id` (for at least one successful call).
3. Trigger a controlled failure (invalid API key) and confirm `error.type=auth_error`.
4. If streaming is enabled, simulate a disconnect and confirm a `stream.disconnect` signal is emitted.

---

## Troubleshooting
**No traces in local dev**
- Verify `OTEL_EXPORTER_OTLP_ENDPOINT` points to a reachable collector.
- Confirm the app sets `service.name`.
- Check docker-compose collector ports and network.

**Request ID missing**
- Ensure the SDK exposes response headers.
- Confirm the gateway header is not stripped by proxies.

**High-cardinality warnings / backend cost spikes**
- Remove user identifiers and document IDs from span attributes.
- Move detailed debug data to local-only logs behind `LOG_SENSITIVE_DEBUG=1`.
