Requirements: Redwood Private audit log export to customer-managed storage

h1. Purpose
This page defines *security and compliance requirements* for exporting audit logs from *Redwood Private* to *customer-managed storage* (typically object storage). It is used by Engineering to implement compliant sinks and by Solutions/CS to validate customer configurations.

h2. Definitions
*Audit logs:* security-relevant records of administrative and control-plane actions within Redwood Private.
*Customer-managed storage:* an account/project owned by the customer (e.g., AWS S3, GCS).

h2. Requirements (MUST)
# *No long-lived static credentials* (access keys) are permitted for audit log export.
# Export auth MUST be via short-lived identity (AWS AssumeRole / GCP Workload Identity Federation).
# Exported objects MUST be encrypted at rest.
## If the sink supports SSE-KMS / CMEK, we MUST support customer-provided KMS key identifiers.
# Exporter MUST provide *at-least-once delivery*.
# Exporter MUST support customer-controlled retention via bucket lifecycle policies (we must not require indefinite retention).
# Export pathing MUST support evidence collection by tenant and by cluster.
# Audit event schema MUST include: `event_time`, `actor_id`, `action`, `resource_type`, `resource_id`, `result`, and a stable `event_id`.
# Exporter MUST produce operational logs/metrics that allow the customer to detect delivery gaps.

h2. Recommended (SHOULD)
* gzip compression for cost
* Daily partitions by default
* Object names that are deterministic and do not leak secrets
* Support an optional customer prefix so they can isolate Redwood logs

h2. Supported sinks (current)
* AWS S3
* Google Cloud Storage

Non-goals (explicit):
* Azure Blob is *not* committed for v1. If requested, capture as a support request and route to Product.

h2. Least privilege guidance
AWS policy must limit:
* `s3:PutObject`, `s3:AbortMultipartUpload`, `s3:ListBucket` (prefix-limited)
* Optional: `kms:Encrypt` on the customer key

GCP permissions must limit:
* `storage.objects.create` on the target bucket/prefix
* Optional: KMS encrypt permission if CMEK is used

h2. Evidence checklist for customer security reviews
When a customer asks Can Redwood export audit logs to our bucket?, we provide:
* This requirements page
* The Private deployment design page
* A sample bucket policy / IAM role template
* A note on delivery semantics and buffering

h2. Tracking changes
Engineering changes that affect these requirements must be reviewed by Security. Link PRs and support tickets here when updated.
