Postmortem: SEV-2 Serving runtime KV-cache eviction storm (2026-01-28)

A change to the runtime memory watermark defaults caused aggressive KV-cache eviction under bursty workloads, leading to repeated recomputation and elevated latency.
p95 latency increased from ~680ms to ~1.9s for chat workloads. Approximately 4% of streaming responses experienced stalls >5s. No data loss.
17:06 UTC: SLO alert for p95 latency on chat route fired (us-east).
17:10 UTC: On-call observed GPU memory oscillations and high cache evictions.
17:18 UTC: Identified runtime config change in 2026.01.28.1 setting low watermark from 0.85 to 0.70.
17:24 UTC: Rolled back runtime config for affected pool; evictions decreased.
17:40 UTC: p95 latency returned to baseline; monitored for stability.
18:02 UTC: Incident resolved.
The serving runtime’s KV-cache manager used the low watermark to trigger eviction. The new default (0.70) was tuned for long-context batch workloads but was applied globally, causing churn for short, bursty chat traffic.
Latency SLO alerts and GPU memory telemetry dashboards.
Rolled back runtime config and pinned chat pools to the previous watermark settings. Disabled the automated config propagation job until validation was added.
Clear dashboards made the symptom obvious. Rollback procedure was well documented.
No workload-specific validation for memory watermark changes; config was promoted without canary on representative chat traffic.
