Fleet gateway choreography and IaC bridge

Summary:
This document defines the fleet gateway choreography pattern and the accompanying IaC Bridge Terraform module used to safely expose GPU-backed inference pools to tenant VPCs and self-serve sandboxes. It combines network design, Terraform conventions, CI/CD gates, and an operational runbook so platform teams can onboard new tenants with predictable SLOs and minimal blast radius.

Scope:
- Applies to: Dedicated GPU fleet endpoints, tenant egress gateways, and burst bridging between regions.
- Not covered: customer-managed on-prem deployments (see eng-private-deployments).

Goals and non-goals:
- Goal: Provide a reproducible, gated path for creating per-tenant gateway stacks that: enforce egress limits, attach short-lived NATs, and integrate with the GPU warm-pool allocator.
- Goal: Ensure every change to network or TF modules passes integration tests that simulate preemption and warmup flows.
- Non-goal: Implement tenant auth (handled by API gateway layer) or full multi-cloud abstraction (this pattern is AWS-first).

High-level architecture (ASCII diagram):

Tenant VPC  <---> Transit VPC (shared) <--[VPC Peering/Transit Gateway]--> Fleet Gateway Proxy(s) --> GPU Pool
                                  |                                         ^
                                  |                                         |
                                  +-> IaC Bridge (Terraform module) ---------+

Components and responsibilities:
- Fleet Gateway Proxy (service: fleet-gw):
  - Terminates tenant connections, enforces per-tenant egress qps and token-budgeting, and routes requests to GPU worker pools.
  - Owned by: eng-infra/networking.
- Egress Shaper (service: egress-shaper):
  - Per-tenant leaky-bucket shaper for burst protection (default: 200 RPS, burst 400 RPS for 30s).
  - Exposes Prometheus metrics: tenant_egress_rps, tenant_egress_burst_exceed_count.
- IaC Bridge (terraform module: redwood/iac-bridge/gateway):
  - Creates Transit attachments, NAT gateways, route table hooks, Security Groups, and SSM parameter records for per-tenant configs.
  - Provides outputs consumed by fleet provisioning pipeline.
- Warm-pool Allocator (service: gpupool-allocator):
  - Ensures N warm GPUs reserved before traffic is routed (configurable per-tier).

SLOs and thresholds:
- Gateways: 99.95% availability per region (rolling 30d).
- Median egress latency (gateway ingress -> worker assigned): < 30ms. P95 < 120ms.
- Tenant egress penalty: if tenant_egress_burst_exceed_count > 5 in 5m, we apply soft-throttling with HTTP 429 and notify tenant owner.

Terraform / IaC patterns (requirements):
- Module pattern: single responsibility modules with explicit outputs. The IaC Bridge module must implement:
  - input variables: tenant_id (string), allowed_cidrs (list), tier (string), warm_gpu_count (number), egress_budget_per_min (number)
  - outputs: transit_attachment_id, gateway_lb_dns, nat_allocation_id, ssm_config_path

Example module usage (terraform snippet):
```
module "tenant_gateway" {
  source = "github.com/redwood/iac-bridge//modules/gateway"
  tenant_id = "acme-corp"
  allowed_cidrs = ["10.12.0.0/16"]
  tier = "gold"
  warm_gpu_count = 4
  egress_budget_per_min = 10000
}
output "gateway_dns" { value = module.tenant_gateway.gateway_lb_dns }
```

CI/CD integration and gating:
1) PR checks (terraform):
   - terraform fmt, tflint, and terraform validate run on every branch.
   - Unit tests with terratest for module input permutations.
2) Integration tests in ephemeral sandbox:
   - Pipeline deploys IaC Bridge into a throwaway tenant sandbox (ephemeral account) and runs the following checks:
     a) Basic connectivity: curl to gateway_dns returns 200 on health endpoint.
     b) Warm-pool readiness: gpupool-allocator reports >= warm_gpu_count within 5 minutes.
     c) Egress shaping: run a synthetic 500 RPS for 30s and assert that >95% of requests see 429 or are queued rather than causing whole-fleet SLO violations.
3) Manual approval gates:
   - Changes that modify transit attachments, NAT behavior, or route tables require at least one network owner approval and one security review.

Preflight checklist (before production apply):
- Confirm tenant_id and allowed_cidrs are accurate.
- Validate warm_gpu_count baseline with product team (default 2 for tier=bronze).
- Confirm cost center tag and billing allocation label (tag: billing:tenant_acme).
- Run terraform plan with -out and review diff in PR.

Rollout procedure (canary -> region -> global):
1) Canary stack: deploy IaC Bridge for a single low-traffic tenant in staging. Verify metrics for 24h.
2) Small region roll: enable for 5% traffic routing (weight on fleet-gw) for 48h.
3) Ramp: 25% for 24h, 50% for 12h, 100% after 72h if no regression.
4) Post-deploy: create a rollout ticket and run a post-deploy smoke checklist.

Rollback steps (fast path):
1) If gateway DNS health checks fail or gpupool-allocator reports shortfall > 2x warm_gpu_count within the canary window, immediately shift traffic to fallback route (fleet-gw-fallback) using the routing control plane.
2) Revert Terraform to previous state using the saved plan: terraform apply "previous-plan.tfplan".
3) Open incident and notify SRE and product owners.

Operational runbook: troubleshooting quick hits
- Symptom: Health check 503 from gateway_dns
  1) Check fleet-gw pods: kubectl -n infra get pods -l app=fleet-gw && kubectl logs <pod> | grep "startup"
  2) Verify warm-pool: curl -s https://gpupool-allocator.internal/tenants/acme-corp/status | jq .ready_count
  3) If ready_count < configured: run allocator diagnostic: /opt/bin/gpu-allocator-check --tenant acme-corp --details and escalate to infra-scheduling.
- Symptom: Unexpected 429s for tenant below quota
  1) Check egress_shaper metrics in prometheus: tenant_egress_burst_exceed_count{tenant_id="acme-corp"}
  2) Inspect SSM config path for egress limits: aws ssm get-parameter --name "/redwood/tenants/acme-corp/egress_limit" --region us-west-2
  3) If limit looks incorrect, apply emergency config patch with the IaC Bridge patcher script (see below).

Emergency patcher (example):
```
# patcher.sh - sets a temporary egress limit in SSM for a tenant
aws ssm put-parameter --name "/redwood/tenants/${TENANT_ID}/egress_limit" --type String --value "20000" --overwrite --region us-west-2
```

Metrics and dashboards to monitor (prometheus/grafana):
- Gateway overview dashboard (team: eng-infra/networking):
  - Series: gateway_available_percent, gateway_median_latency_ms, gateway_p95_latency_ms, tenant_egress_rps, tenant_egress_burst_exceed_count.
- Cost dashboard: NAT-billing-per-tenant, warm_gpu_hourly_rate, idle_gpu_hours.

Security and least-privilege notes:
- Terraform service principal must use scoped IAM roles: Ec2:CreateNatGateway, Ec2:CreateRoute, SSM:PutParameter, STS:AssumeRole for tenant account.
- All tenant configs stored in SSM must be encrypted with CMKs; IaC Bridge creates and references key aliases /alias/tenant-<id>-cfg.

CI/CD test harness (example commands):
- Run local terratest suite: go test ./test -v -run TestGatewayModule -timeout 30m
- Run synthetic egress test (k6): k6 run --vus 200 --duration 30s tests/egress-shaper.js --env TARGET=https://gateway-dns/health

| Scenario | First check | Escalation owner | Runbook ticket template |

Cost implications and knobs:
- NAT gateways are billed hourly and by GB egress. Recommend shared NAT pools for sandbox accounts and per-tenant NAT only for gold-tier customers.
- IaC Bridge exposes a variable to opt-in for shared or dedicated NAT (variable: nat_mode = "shared" | "dedicated").

Appendix A — Sample policy (security group minimal rules):
```
resource "aws_security_group" "gateway_sg" {
  name = "gateway-sg-${var.tenant_id}"
  vpc_id = var.transit_vpc_id
  ingress {
    from_port = 443
    to_port = 443
    protocol = "tcp"
    cidr_blocks = var.allowed_cidrs
  }
  egress {
    from_port = 0
    to_port = 0
    protocol = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
  tags = var.common_tags
}
```
