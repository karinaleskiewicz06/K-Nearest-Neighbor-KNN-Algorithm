Sev1/Sev2 incident process (engineering oncall)

# Overview
This page defines Redwoods standard process for Sev1 and Sev2 production incidents. It includes the required roles, decision points, and required outputs.

# Severity definitions (summary)
- **Sev1:** Widespread customer impact (majority of traffic impacted) or critical functionality unavailable in 1+ regions.
- **Sev2:** Significant degradation (elevated latency or elevated 5xx) affecting a subset of customers/regions/routes.

# When to declare
Declare an incident if any of the following are true:
- sustained 5xx rate increase beyond alert thresholds
- sustained p95 latency increase beyond SLO thresholds
- widespread streaming disconnects
- repeated crash-loop or GPU OOM affecting availability

# Required roles
- **Incident Commander (IC):** owns coordination, decisions, approvals for mitigations
- **Operations Lead (Ops):** executes changes and keeps timeline updated
- **Comms Lead:** posts status updates, coordinates with Support/CS
- **Subject Matter Expert (SME):** runtime/platform expert doing deep investigation

# Mandatory steps
1. Create incident Slack channel in #incidents (or use incident-bot)
2. Assign roles (IC, Ops, Comms, SME)
3. Establish update cadence (default: 15 minutes internal, 30 minutes external if impacted)
4. Identify mitigation candidates (rollback, feature flag changes, traffic shifting)
5. If an emergency production change is required: follow EPC policy approvals and create EPC record

# Timeline requirements
The incident timeline must include:
- first detection + alert source
- mitigations attempted and exact deploy/config times
- impact changes observed after each mitigation
- customer comms times (status page + direct comms)

# Exit criteria
- error rates and latency have returned to baseline and remain stable for 30 minutes
- support queue is stabilizing (no new spike of related tickets)
- rollback plan documented if the mitigation is temporary

# After-action requirements
- Sev1: postmortem required
- Sev2: incident review required if customer-visible or if EPC executed
- Follow-up items must be tracked in Linear
