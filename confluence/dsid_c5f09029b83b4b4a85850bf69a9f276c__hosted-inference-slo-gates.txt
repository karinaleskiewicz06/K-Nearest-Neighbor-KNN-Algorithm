Hosted inference SLO gates for model rollouts

# Purpose
This page defines the **SLO-based gates** and monitoring checklist for progressing a **Hosted API** model rollout. These gates are evaluated at each canary step.

# Rollout gating principles
- Prefer simple, measurable signals.
- Gate on customer-impacting metrics.
- If there is ambiguity, pause the ramp and investigate rather than continuing.

# Required dashboards
During a rollout, you must have the following dashboards open (prod, correct region):
- Hosted API Overview: request rate, p95 latency, error rate
- Inference runtime: queue time, batcher backlog, GPU utilization
- Router: fallback share, fallback reasons
- Quality proxies: structured output validity (if enabled), tool schema validity (if enabled)

# Gates (must remain green to proceed)
Evaluate over the most recent 1020 minutes after each traffic shift.

## Gate 1: Availability
- Total 5xx rate for the route <= **0.5%**
- Timeout rate <= **0.2%**

## Gate 2: Latency regression
Compare to baseline (same day, prior hour):
- p95 latency increase <= **10%**
- p99 latency increase <= **15%**

## Gate 3: Saturation / capacity health
- Primary queue time p95 <= **200 ms**
- GPU utilization <= **92%** sustained (to leave headroom for bursts)
- Batcher backlog not monotonically increasing for > **5 minutes**

## Gate 4: Fallback sanity (if fallback enabled)
- Fallback share <= **10%** sustained after the first 10 minutes of a step
- No single fallback reason dominates > **80%** for more than 5 minutes (indicates systematic issue)

## Gate 5: Output validity (conditional)
If the route requires structured output or tool calling:
- Structured output validity >= **99.5%**
- Tool schema validity >= **99.0%**

# What to do when a gate fails
- Pause the rollout (do not increase traffic).
- If availability/latency is customer-impacting, reduce primary share or rollback.
- If fallback share is high, investigate capacity and health; do not assume fallback is a permanent fix.
- Open an incident if user impact is material or if an SLO burn is detected.

# Notes
- These are default thresholds; certain enterprise routes may have stricter requirements in their runbooks.
- Any threshold changes must be recorded in the release ticket and reviewed by SRE.
