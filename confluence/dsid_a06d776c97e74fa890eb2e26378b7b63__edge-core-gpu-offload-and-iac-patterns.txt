Edge-to-Core GPU Offload: Network, Egress Controls, and IaC Patterns

Summary:
This doc describes a standardized, SLO-driven pattern for offloading inference work from edge-deployed GPU nodes to core/cloud GPU pools. It covers networking and egress controls, Terraform/IaC module patterns, CI/CD promotion guidance, operational runbook steps for capacity and cost incidents, and the telemetry/alerting contract teams must implement. The goal is to enable predictable performance and cost visibility while preserving tenant isolation and safety for regulated workloads.

When to use this pattern:
- Edge device pools (on-prem, retail sites, customer-managed racks) occasionally need to offload heavy sequences or large-batch evals to core GPUs.
- Workloads that degrade tail latency on the edge when run locally (e.g., long-context generations, large batch retraining).
- Customers that require local inference for privacy-sensitive inputs but allow aggregated or redacted offload.

High-level design:
1) Decision boundary: a local router component (edge-router) applies policy rules to decide if a request stays local or is offloaded. Policies consider sequence length, model family, tenant egress budget, and KV cache hit.
2) Secure egress tunnel: offloads travel over a mutually authenticated tunnel (mTLS or AWS PrivateLink) with per-tenant service accounts and scoped IAM roles.
3) Cost-aware throttling: an egress controller evaluates daily/rolling credits and applies backpressure or degradation (model quantized variant) when budgets approach thresholds.
4) Fallback/hedging: always attempt local quick-pass; if local slow-path begins, start a hedged request to core and cancel the slower path when the first completes.
5) IaC modules: a composable Terraform module exposes variables for routing policies, egress budgets, IAM bindings, and network endpoints to be consumed by both edge and core stacks.

SLOs and thresholds (recommended):
- Successful offload completion (core) 99.95% per 7d window.
- Median offload latency (edge->core->resp) < 1200ms for short sequences, < 2000ms for long sequences.
- 99th percentile < 5s (non-real-time batch workloads excluded).
- Egress budget warning at 70% of daily/rolling budget; automatic soft-throttle at 90%; hard block at 100% unless override by oncall.

Telemetry & dashboards (required):
- Metrics (per-tenant): offload_requests_total, offload_success_total, offload_latency_ms (p50/p95/p99), egress_bytes, egress_cost_estimate_usd.
- Traces: distributed tracing across edge-router -> tunnel -> core-serving (span naming: edge.router.offload, network.tunnel.tx, core.inference.serve).
- Alert rules: offload_success_rate < 99.9% over 5m (sev2), egress_budget_usage >= 90% (cost-alert sev2), offload_latency_p95 >= 3s for >10% of tenants (perf-eng sev2).

Terraform / IaC patterns (example):
- Module responsibilities:
  - networking: provision PrivateLink/NLB endpoints, VPC peering config, subnet routing assertions
  - security: create offload-specific IAM roles, STS trust policies, KMS keys for in-flight key wrapping
  - service: register edge-router service discovery entry and per-tenant egress quota object

Example module interface (variables and defaults table):
| variable | type | default | description |
|---------|------|---------|-------------|
| region | string | "us-west-2" | Core region for offload endpoints |
| offload_network_mode | string | "privatelink" | one of ["privatelink","mtls","vpn"] |
| daily_egress_budget_gb | number | "5" | per-tenant soft budget in GB/day |
| enable_burst | bool | "true" | allow short burst above budget with analytics capture |

Terraform snippet (consuming module):
```
module "edge_to_core_offload" {
  source = "git::ssh://git.example.com/infra/terraform-modules.git//edge-offload?ref=v1.2.0"
  region = var.core_region
  offload_network_mode = "privatelink"
  daily_egress_budget_gb = lookup(var.tenant_defaults, "egress_budget_gb", 5)
  enable_burst = true
}
```
Network design patterns and constraints:
- Use regional PrivateLink or equivalent to avoid public egress where possible. If PrivateLink is unavailable, require mTLS over NAT egress with strict IP allowlists.
- Split control plane vs data plane: control plane (service discovery, policies) should use dedicated control subnets with least-privilege security groups. Data plane traffic flows over dedicated attachment subnets with high MTU and flow logs enabled.
- Egress cost accounting: tag offload flows with per-tenant identifiers at the NAT/proxy layer for billing. Enforce egress marking headers at the edge-router so core billing pipelines can attribute cost.

CI/CD and promotion guidance:
1) Module versioning: follow semver for the edge-offload module. Breaking changes must have a migration guide file in the module repo.
2) Integration tests: provide a lightweight emulation harness that spins up a fake core endpoint and validates hedging, cancelation, and egress marking flows. Run in PRs and nightly canaries.
3) Canary rollout: deploy edge-router changes to a single tenant or 2% of edge nodes, monitor p99 latency and offload success rate for 24 hours before broader promotion.
4) Safety gates: terraform plan must include a diff check that ensures no new open egress rules are added without an explicit reviewer tag.

Operational runbook: Offload incident flow
- Trigger: alert for offload_success_rate < 99.9% or offload_latency_p95 spike.
- Owner: oncall-infra (primary) -> runtime-team (secondary).
Steps:
1) Triage: check dashboard for tenant impact, identify whether failures are network (tunnel) or core serving errors.
2) Confirm NAT/PrivateLink health: run quick checks from an affected edge node:
   - curl -v https://offload-core.example.internal/healthz (expect 200)
   - tcpdump -i <iface> 'tcp port 443' -w /tmp/offload.pcap (capture 30s)
3) If tunnel down: verify edge-router certificate validity, rotate cert if expired, and restart edge-router with zero-downtime rolling restart: kubectl rollout restart deploy/edge-router -n infra-edge.
4) If core saturated: validate core GPU pool metrics (utilization > 85%), check autoscaler and queued_requests_total. Scale path:
   - Increase reserved_capacity in the dedicated GPU autoscaler manifest (path: //deploy/core/autoscaler/overrides.yaml) and apply via the safe-promote pipeline (ci/cd).
5) If egress budget breach: notify tenant with pre-defined template, optionally flip tenant policy to local-only (toggle in tenant policy store) and credit-back actions.
6) Post-incident: open an incident ticket, attach traces, and run a short RCA focusing on whether router heuristics underpredicted sequence length or cache misses spiked.

Safety and compliance notes:
- PII: only allow offload if inputs are marked offloadable by upstream PII classifier. Documented flag: input_metadata.offload_allowed = true.
- Audit logging: every offload decision must include a reason code (e.g., cache_miss, seq_len_gt_2048, model_not_supported) and recorded to a tamper-evident audit log persisted for 90 days.
- KMS: use envelope encryption with per-tenant KMS keys when moving sensitive payloads; module exposes a kms_key_id variable.

Rollback checklist for a bad module deploy:
1) Revert to previous module tag via terraform workspace and apply.
2) If terraform revert fails due to drift, run the emergency manual remediation script located in //infra/tools/edge-offload/fix_drift.sh and notify oncall.
3) Ensure tenant egress policies are re-applied and validate with the integration harness.
