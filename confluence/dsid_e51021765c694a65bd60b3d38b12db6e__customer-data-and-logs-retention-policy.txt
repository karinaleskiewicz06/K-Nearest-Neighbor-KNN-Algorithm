Customer data + logs retention policy (Hosted, Dedicated, Private)

# Purpose
This page defines the default retention and deletion timeframes for customer data and operational logs across Redwood Inference products (Hosted API, Dedicated, and Private).

# Definitions (quick)
- Customer content: prompts, files, and model outputs (request/response payloads).
- Operational logs: API gateway logs, runtime logs, error logs, and request metadata (e.g., request id, status code, latency).
- Debug payload logging: optional feature that stores limited request/response payloads for troubleshooting.
- Audit logs: security-relevant actions (e.g., login, key creation, RBAC changes).

# Default retention windows
## Hosted API (Redwood-managed)
- Customer content (prompts/outputs): Not stored persistently by default.
- Debug payload logging (if explicitly enabled for an org): 7 days retention.
- Operational request logs (metadata, not payloads): 14 days retention.
- Tracing spans linked to request ids (no payloads): 14 days retention.

## Dedicated (Redwood-managed, isolated capacity)
- Customer content (prompts/outputs): Not stored persistently by default.
- Debug payload logging (if enabled): 7 days retention.
- Operational request logs (metadata, not payloads): 14 days retention by default.
- Enterprise retention add-on (contracted): Operational request logs can be extended to 30 days (requires Security approval and support runbook change).

## Private (VPC / on-prem)
- Customer content + operational logs: Retention is customer-configurable because storage is customer-managed.
- Private default installer values (if customer does not change settings): 30 days for operational logs in the in-cluster log store.
- Redwood control-plane access logs (when Redwood engineers access the private control plane for support): 90 days retention in Redwood systems.

# Deletion requests
- If a customer submits a deletion request for stored data within Redwood-managed systems (e.g., debug payload logs), Redwood will complete deletion within 30 days of verification of the request.

# Notes and guardrails
- Debug payload logging must be explicitly enabled and is intended for time-bounded troubleshooting.
- Any change to retention windows for Redwood-managed systems requires Security + SRE review and an update to the customer-facing Security FAQ.
