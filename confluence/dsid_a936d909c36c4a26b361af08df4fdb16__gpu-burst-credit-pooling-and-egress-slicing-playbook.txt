GPU burst credit pooling and egress slicing playbook

Summary
-------
This playbook describes the GPU burst credit pooling and egress-slicing pattern we use to provide predictable tenant-level throughput while minimizing egress cost surprises. It covers architecture, Terraform module usage, runtime configuration, CI/CD validation, monitoring, and incident response steps.

Scope
-----
Applies to: multi-tenant GPU clusters used for inference workloads across Hosted/Dedicated/Private modes when tenant traffic must be rate-controlled at the network egress boundary. It does NOT cover storage-tiering or application-level rate limits.

Goals and guarantees
--------------------
- Per-tenant egress fairness: tenants should not exceed their granted burst credits for outbound bandwidth.
- Predictable billing: cost attribution to tenant owners must align with observed egress volume within 5% monthly.
- Safety SLOs: system must prevent noisy neighbors from degrading cluster-level packet loss beyond 0.5% and tail latency beyond the defined thresholds for control-plane operations.

High-level architecture
-----------------------
- Credit Manager (control-plane service): centralizes tenant burst credit balances, issues refills, and exposes a consistent API for proxies to query allowances. Owned by infra-networking.
- Edge Egress Proxies (data-plane): per-node or per-subnet sidecar proxies enforce token-bucket shaping and apply per-tenant slices. Implemented as a fast userspace proxy (Envoy with custom filter or small Rust proxy).
- Accounting pipeline: streaming ingest into billing topics (Kafka) with per-flow annotations and sampled packet headers for verification.
- Terraform module: exposes variables for credit parameters, routing attachments, and IAM bindings for cross-account proxy roles.

Design details
--------------
1) Credit model
- Each tenant has a persistent monthly allocation (egress_bytes/month) and a burst_credit pool measured in bytes.
- Burst refill signals occur at configurable intervals (default 5m). Refill rate = base rate + carryover (up to max_pool).
- Credits consumed on egress; when depleted, requests are shaped to a default throttled rate or redirected to a lower-cost model tier.

2) Slicing enforcement
- Enforcement points live as a) per-node sidecar for low-latency enforcement and b) an aggregated per-subnet egress gateway for legacy workloads.
- Proxies implement the token-bucket algorithm with per-tenant state keyed by tenant-id header or IP/MAC mapping issued by the Credit Manager.
- Optional kernel offload (tc + fq_codel) is used for best-effort shaping; proxy remains authoritative for precise accounting.

Configuration reference (table)
-----------------------------
| Variable | Default | Description |
| --- | --- | --- |
| burst_refill_interval | 300s | Control-plane refill cadence |
| base_rate_per_tenant | 128KiB/s | Sustained egress guaranteed per tenant |
| max_burst_pool | 10GiB | Max bytes a tenant may accumulate |
| shaping_strategy | token-bucket | Enforcement algorithm (token-bucket | leaky-bucket) |
| enforcement_mode | proxy-first | proxy-first | kernel-fallback |

Terraform module usage example
------------------------------
Use the module in the tenant account to create the necessary IAM role and attach proxy routing. Example snippet: 

```hcl
module "egress_slicing" {
  source = "git::ssh://git@repo.company/internal-terraform//egress-slicing-module?ref=v1.4.0"
  tenant_id = "acme-corp"
  base_rate_per_tenant = "128KiB"
  max_burst_pool = "10GiB"
  attach_vpc_subnet_ids = ["subnet-abc123", "subnet-def456"]
  enforcement_mode = "proxy-first"
}
```

Important module outputs:
- proxy_role_arn (string)
- routing_attachment_id (string)
- accounting_topic (string)

Proxy bootstrap and config (example)
----------------------------------
- Proxies fetch per-tenant policy via: GET https://credit-manager.internal/v1/policies?tenant_id=<id>
- Example JSON policy (simplified): 
```json
{
  "tenant_id": "acme-corp",
  "base_rate_bps": 1048576,
  "max_burst_bytes": 10737418240,
  "priority": "standard"
}
```
- Local kernel shaping fallback (example commands to apply on node):

sudo tc qdisc replace dev eth0 root tbf rate 128kbit burst 32k latency 50ms

CI/CD: validation and gating
---------------------------
- Terraform changes: PR must include a plan with diff checks that show no IAM role escalations and no subnet attachment removals. Add an automated policy test that runs "terraform validate" and checks module variable ranges.
- Proxy builds: unit tests for token-bucket invariants; integration test spins up a 3-node k8s cluster in ephemeral environment that runs a synthetic tenant with configurable burst pattern.
- Performance test: nightly benchmark that exercises 95th/99th percentile enforcement accuracy. Goodness criteria: accounting error <= 1% and enforcement latency < 2ms added at proxy.

Observability and metrics
------------------------
Emit the following metrics with tenant tags:
- egress.bytes_total (counter)
- egress.burst_credits_remaining (gauge)
- egress.throttled_bytes (counter)
- egress.enforcement_latency_ms (histogram)
- egress.drop_rate (gauge)

Important dashboards and alerts
- Dashboard: Tenant Egress Overview (by tenant, last 30d)
- Alert: tenant_burst_credit_negative -> P3 to infra-networking if any tenant balance < 0 for > 10m
- Alert: accounting_lag_seconds > 120 -> P2 (investigate Kafka consumer backlog)
- Alert: cluster_wide_egress_drop_rate > 0.5% -> P1 (possible noisy neighbor)

Cost attribution and billing
---------------------------
- Accounting pipeline produces per-tenant hourly summaries landed in billing S3 bucket with schema: tenant_id, window_start, window_end, bytes_egressed, observed_cost_usd, verified_flag.
- Reconciliation job runs nightly to compare accounting-based charges with cloud egress metering. Tolerance target: 5% discrepancy.

Runbook: incident scenarios and steps
-----------------------------------
1) Noisy tenant (sustained high egress)
- Detect: alert cluster_wide_egress_drop_rate or tenant.throttled_bytes spike.
- Immediate: add emergency cap via Credit Manager API: POST /v1/admin/cap?tenant_id=<id>&cap_bytes=1GiB
- Mitigation: move tenant to isolated subnet and create a temporary per-tenant gateway. Notify customer success.
- Postmortem: include evidence from accounting topic and schedule tenant quota review.

2) Accounting consumer lag (billing pipeline)
- Detect: accounting_lag_seconds > 120
- Immediate: scale Kafka consumer group (infra-tools consumer-scale --group billing-consumers --replicas 4).
- If backlog persists, enable compute-only fallback where proxies write hourly manifest files to S3 for temporary billing ingestion.

3) Proxy crash loop or elevated enforcement latency
- Detect: pod restart count > 5 in 10m or enforcement_latency_ms 99th > 10ms
- Immediate: redirect traffic to kernel shaping fallback by toggling enforcement_mode in Credit Manager (fast-path toggle endpoint).
- Replace proxy build with last-known-good image; roll back PR if the change is recent.

Ownership and run cadence
------------------------
- Owner: infra-networking team (primary), billing-team (secondary).
- On-call: infra-networking oncall rotates weekly; paging rules configured for P1/P2 alerts.
- Review cadence: quarterly policy review to adjust base_rate and max_burst_pool based on usage trends.

Testing checklist before rollout
-------------------------------
- [ ] Terraform plan shows only additive changes to IAM and routing attachments
- [ ] Integration tests show accounting error <= 1% in staging
- [ ] Performance test shows enforcement latency < 2ms for 95th pct
- [ ] Billing reconciliation job passes on staging dataset

Appendix: example debug commands
--------------------------------
- Query tenant balance: curl -sS "https://credit-manager.internal/v1/balance?tenant_id=acme-corp"
- Force refill for tenant (admin only): curl -X POST "https://credit-manager.internal/v1/admin/refill" -d '{"tenant_id":"acme-corp","bytes":104857600}'
- Temporarily cap egress on a node: sudo tc qdisc replace dev eth0 root tbf rate 1mbit burst 64k latency 100ms
